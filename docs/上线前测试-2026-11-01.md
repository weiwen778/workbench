# 工作台性能与功能验收（2026-11-01）

## 结论

已覆盖的核心功能流程通过；没有在本轮覆盖范围中发现数据丢失或未受保护的并发覆盖。低负载下响应可用，高并发性能未达到此前提出的 P95 <150ms、P99 <300ms 目标，不能据此宣布全面通过上线验收。

测试阶段仅在本地执行；后续发布与云端验证另行记录。测试使用独立数据库和模拟数据；保留测试库和原始结果便于复现。

## 环境与方法

- Windows Chrome + WSL Ubuntu，12 个逻辑 CPU，约 25GB WSL 可用配置总内存。
- Python 3.10、Uvicorn 单 Worker，无 `--reload`；SQLAlchemy 同步数据库访问，PostgreSQL 14。
- 当前 Docker 配置同样启动单 Worker，但目标为 Python 3.12 / PostgreSQL 16，API 内存限制640MB。此次未施加相同容器资源限制，也未在云端执行，因此结果不能视为云端容量承诺。
- 性能服务仅监听回环地址18746；浏览器功能服务18747。用户日常工作台18081保持使用原数据库。
- 混合压测：80%列表读取、15%便利贴更新、5%图表聚合；这是封闭用户模型，并非全部业务或真实用户到达流量模型。目标 RPS 是节流目标，实际值另记。
- 年度模拟数据：11张业务表、189个字段、5,004条表格记录、9,672条打卡、240条待办、43篇笔记、10个看板；另增加40组导航数据。容量专项增加1千、1万、5万行表，1千和1万行含公式。
- 最初普通负载样本与构建时间有交叠；最终重新采集 `normal-final`，下表普通负载使用最终值。其他程序运行在同一台电脑，仍存在共享主机干扰。

## 性能结果

| 场景 | 持续时间 | 请求数 | 实际吞吐 | P95 | P99 | 请求错误 |
|---|---:|---:|---:|---:|---:|---:|
| 健康检查、10并发 | 15秒 | 5,378 | 357.99/s | 40.76ms | 59.86ms | 0 |
| 普通混合负载、10用户、目标20/s（最终复测） | 30秒 | 600 | 19.95/s | 151.00ms | 205.29ms | 0 |
| 高峰混合负载、30用户、目标60/s | 30秒 | 1,795 | 58.90/s | 387.17ms | 599.31ms | 0 |
| 60用户不节流连续请求 | 30秒 | 2,229 | 71.32/s | 1,305.93ms | 1,616.93ms | 0 |
| 短时稳定性、10用户、目标20/s | 180秒 | 3,600 | 19.96/s | 158.30ms | 224.42ms | 0 |

- 高峰主要慢在图表聚合和打卡；60/s阶段两者P95分别约786ms和424ms。
- 三分钟稳定性：API RSS从168.1MB到166.1MB，区间163.3–168.1MB；数据库连接最多11（含监控连接），死锁0。本样本未见持续内存增长，但三分钟不能证明无内存泄漏。
- 60用户阶段API峰值RSS172.4MB，进程CPU峰值148.5%（约1.49个逻辑核心，不是整机148.5%）。
- Agent专项：10个并发任务，200次GET与200次PATCH全部200；一轮“读取+写入”P95约862ms、P99约1,318ms。不能与单请求P99直接等同，但表明高频回写存在等待。
- Agent和浏览器同时修改同一版本：返回409和200，避免静默覆盖；Agent令牌访问浏览器专用接口返回401。

## 数据量与前端专项

| 数据量 | PostgreSQL分页50行中位数 | 完整workspace中位数 | workspace体积 | 本机浏览器打开 |
|---|---:|---:|---:|---:|
| 1,000行（含公式） | 18.08ms | 60.54ms | 约317KB | 545ms，JS堆约23MB |
| 10,000行（含公式） | 19.69ms | 535.12ms | 约3.19MB | 990ms，JS堆约45MB |
| 50,000行 | 28.21ms | 约20ms返回容量限制 | 错误提示127B | 增强视图限制提示，经典分页视图可用 |

- 浏览器打开时间为Windows Chrome经本机网络访问隔离SQLite服务的单次样本；表中接口时间来自独立PostgreSQL服务，不能相减或当成同一请求链路。
- 增强表格明确限制10,000行；虚拟表来源合计最多20,000行、输出最多10,000行。大于限制时需要拆分或使用经典分页，不能承诺5万行增强表格。
- 增强视图为一次加载全部数据后在前端分析，10,000行仍有约3.2MB未压缩JSON传输；弱网开表体验需后续优化。
- 3次冷缓存手机模拟：390px、CPU降速4倍、100ms网络延迟、375KB/s；登录页FCP/LCP约3,080–3,108ms，传输约844KB，JS约454KB。本地静态服务不压缩，不能等同生产Nginx已开启Gzip的表现，也不是完整Lighthouse评分。

## 本轮修复

1. 网址分类原本在侧栏挂载时立即请求，图片测试发现进入图片模块后仍出现无关API请求。改为进入网址模块或展开网址导航时加载；图片完整流程复测无API/上传请求，分类新建与刷新也复测通过。
2. Agent浏览器验收脚本仍使用旧设置路径和重复标题定位。更新为Agent设置路由及实际卡片选择器，完整创建、权限、回写、撤销流程通过。此项是测试维护，不是业务功能变更。

## 完整程度与尚未通过的准入项

| 项目 | 状态与处理建议 |
|---|---|
| 核心数据操作与冲突保护 | 已覆盖流程可用；适合进入低并发试运行验收准备 |
| 高并发响应 | 未满足既定目标；先分析图表聚合、打卡及公式回写热路径，再评估Worker和连接池，避免直接增加连接数 |
| 大数据增强表格 | 有明确边界；5万行仅经典分页通过，增强模式不支持 |
| 网址分类管理闭环 | 已有创建和选择，但尚无分类重命名、删除入口；作为功能缺口记录，本轮不扩展开发 |
| 网站图标与名称 | 名称有网页读取与域名兜底；图标依赖外部URL，没有离线缓存，不保证所有网站图标可访问 |
| 长时间稳定性 | 只做3分钟短测，4–8小时持续负载尚未执行 |
| 云端等效验证 | 尚未在Python3.12/PostgreSQL16及云端CPU、容器内存限制下复现；公网网络、HTTPS与Nginx压缩后的首屏未验收 |
| 数据备份恢复及发布回退 | 本轮不部署，也没有在目标云环境执行恢复与回退演练 |

建议优先级：①在云端等效的隔离环境复测并明确预期用户数；②针对图表/打卡/Agent热路径优化后同场景对比；③进行4–8小时稳定性测试；④补完必要的管理闭环；⑤通过后再执行备份恢复演练和部署验收。
