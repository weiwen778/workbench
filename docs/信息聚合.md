# 信息聚合

Nexus 内的公开资讯聚合模块：热榜、个人 RSS/Atom 订阅、日历看板（赛事、节日、平台规则与常用入口），以及英文标题中文翻译。抓取全部由后端完成，浏览器只通过 Nexus API 读取；不要求用户把平台 Cookie 或账号密码交给 Nexus。

入口：侧栏「信息聚合」→ `/feeds`。三个页签：热榜、我的订阅、日历。日历页的详细设计见 [`信息聚合-日历看板.md`](./信息聚合-日历看板.md)。

## 1. 来源与真实接入结果

### 热榜 · 国内

| 来源 | 接入 | 本次环境实测 |
| --- | --- | --- |
| 微博热搜 | 优先 `DailyHotApi` 的 `/weibo`，不可用时回退微博公开热搜接口 | 50 条；平台原顺序；搜索详情链接；实际提供方「微博公开热搜接口」 |
| 知乎热榜 | 优先 `DailyHotApi` 的 `/zhihu`，不可用时回退知乎公开热榜接口 | 30 条；原顺序；热度、摘要、问题链接；实际提供方「知乎公开热榜接口」 |
| B 站热门 | 优先 `DailyHotApi` 的 `/bilibili`，不可用时回退哔哩哔哩热门接口 | 20 条；标为「热门」；原顺序；播放量；实际提供方「哔哩哔哩热门接口」 |

`DailyHotApi` 地址可配置（`WB_FEED_DAILYHOT_BASE_URL`）。本机验证时官方演示域名 `api-hot.imsyy.top` 无法解析，因此三个国内源使用了直连平台公开接口；直连也失败时会保留错误状态和原始入口。已单独启动兼容实例验证 `/zhihu`、`/bilibili` 路由结构可用；其 `/weibo` 适配上游结构变化失败，因此业务实现保留直连回退。

### 热榜 · 海外

| 来源 | 接入 | 本次环境实测 |
| --- | --- | --- |
| Google Trends 美国 Trending Now | `https://trends.google.com/trending/rss?geo=US`，地址可配置 | **当前部署网络访问 `trends.google.com:443` 超时**。页面保留「暂不可用」、错误和来源入口；配置可达地址后自动恢复 |

### 我的订阅

首次为当前账号预置：

- Hacker News 首页 RSS：`https://hnrss.org/frontpage`
- OpenAI News RSS：`https://openai.com/news/rss.xml`

本次环境实测：Hacker News 20 条，OpenAI News 500 条（按配置上限保留最近 500 条），均能读取发布时间、原文链接和讨论链接。Hacker News 优先打开原文，另提供「讨论」链接。

用户可粘贴公开 RSS/Atom 地址，先验证来源名称、类型和可用条目，再保存。实测用 Rust Blog Atom（`https://blog.rust-lang.org/feed.xml`）完成新增、翻译、收藏、删除，并确认删除后收藏条目仍可在「收藏」筛选中回看。

### 日历看板

第三个页签从原来的「常用信息源」升级为「日历」，同一页展示 5 个区块：

| 区块 | 内容 | 数据方式 |
| --- | --- | --- |
| 日历 | RunSignup 全球赛事 + 美国 11 个联邦假日 | 后端自动抓取 RunSignup，节日本地计算 |
| 数据 1 | 最近 30 条订阅文章，未读优先 | 复用订阅条目 |
| 数据 2 | 阿里国际站规则最近 10 条 | 公开 JSON API |
| 数据 3 | 1688 规则最近 10 条 | mtop 公开接口 + 签名 |
| 数据 4 | TEMU 卖家中心、Pinterest Trends、RunSignup 查询入口 | 只提供入口，不抓取 |

公共源复用 `feed_snapshots` 的 `common:*` 快照，失败时保留上次成功数据；手动刷新有 60 秒冷却。TEMU 需要登录态，Pinterest Trends 在当前部署网络不可达，两者只保留入口。完整字段、接口和已知限制见 [`信息聚合-日历看板.md`](./信息聚合-日历看板.md)。

## 2. 页面行为

### 热榜

- 国内、海外分区；每个来源独立卡片，不跨平台混排、不跨平台去重。
- 默认显示前 10 条或上游可用条数，可展开全部。
- 显示平台、实际数据提供方、状态、最近成功抓取时间、源提供的榜单更新时间、条目数。
- 显示源给出的排名/热度；Google 没有名次时不占名次位。
- 搜索型链接标「搜索详情」，趋势话题标「查看话题」，普通条目直接打开原文。
- 单源刷新、刷新全部；首屏先读缓存，再后台刷新；连续请求由后端合并。
- 单源失败不影响其他来源；有缓存时显示旧数据和旧成功时间，并标记「显示缓存」。
- 状态区分：已更新、刷新中、显示缓存、暂不可用、暂无条目、等待更新。

### 我的订阅

- 左侧来源列表：全部来源、每个订阅、未读数、启用/停用状态、最近成功时间。
- 条目按发布时间由新到旧；缺少发布时间时按发现时间排序，并显示「收录时间」。
- 来源筛选、未读筛选、收藏筛选；支持加载更多。
- 可标记已读/未读、收藏/取消收藏；刷新后保留。
- 添加订阅：地址验证成功后显示来源名称、RSS/Atom 类型、条目数和前 5 条样例。
- 重命名、停用/启用、删除、手动刷新。
- 停用后不再拉取新条目，已有条目和状态保留。
- 删除为软删除：订阅从列表消失，已收藏条目保留，可在「收藏」中看到「订阅已移除」。
- 删除后重启/升级不会恢复默认订阅；默认初始化按 `default_key` 幂等执行。

### 翻译

- 复用 Nexus 现有翻译连接、密钥、模型和 `/settings/translation` 配置。
- 英文标题下方显示中文译文；中文内容不显示翻译按钮。
- 支持单条翻译和「翻译可见」，前端按 20 条分批，后端并发上限 3。
- 译文按 `原文哈希 + 目标语言` 缓存；相同标题不重复提交；标题变化后产生新缓存键。
- 未配置翻译服务时，原文、跳转、已读和收藏仍可用，并提示去配置。
- 翻译失败返回原文和错误状态；可按条重试。已有缓存仍可显示。
- 正文翻译、日报和外部提醒不在首版。

## 3. 后端设计

### 数据表（迁移 `20261114_d6e7f8a9b0c1_feeds.py`）

- `feed_snapshots`：每个公共热榜来源一行；`entries` JSON 为最近一次完整有效快照，保留顺序；另存 provider、榜单更新时间、最近尝试/成功、错误码、ETag、Last-Modified、失败次数、下次尝试时间、抓取锁。
- `feed_subscriptions`：按用户隔离；URL 规范化哈希、标题、类型、启用状态、默认键、ETag、失败退避、软删除时间。
- `feed_entries`：订阅条目；`(subscription_id, entry_key)` 唯一去重，保存外部 ID、标题、链接、安全纯文本摘要、语言、发布时间、发现时间、已读/收藏时间、讨论链接。
- `feed_translations`：跨用户共享标题翻译缓存；`(text_hash, target_lang)` 唯一。

### 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/feeds/hot` | 热榜缓存、来源状态、中文译文、翻译状态 |

| GET | `/api/v1/feeds/subscriptions` | 幂等预置默认订阅并返回列表 |
| POST | `/api/v1/feeds/subscriptions/preview` | 验证 URL 并返回来源名称、类型、样例 |
| POST | `/api/v1/feeds/subscriptions` | 新增或恢复订阅 |
| PATCH | `/api/v1/feeds/subscriptions/{id}` | 重命名、启停 |
| DELETE | `/api/v1/feeds/subscriptions/{id}` | 软删除，保留条目和收藏 |
| POST | `/api/v1/feeds/subscriptions/refresh` | 按订阅/全部刷新 |

### 刷新与缓存

- 未新增 APScheduler 等调度依赖；复用 Nexus 现有 asyncio 生命周期，在 `lifespan` 中启动轻量 `refresh_loop`，随 Nexus 启停。
- 默认周期：热榜 900 秒、RSS 1800 秒、调度巡检 60 秒；公共源中阿里/1688 规则 3600 秒、RunSignup 21600 秒。均可通过环境变量覆盖。
- 启动后首轮自动拉取；打开页面先读缓存，再请求后台刷新。
- 单进程内用保留集合合并同源请求；多进程/多实例用数据库行锁和 `locked_until` 避免重复抓取。抓取锁在异常退出后自动过期。
- 成功后替换完整快照；失败/解析错误不覆盖最近成功快照，分别记录最近尝试和最近成功时间。
- 合法空列表保存为空快照并显示「暂无条目」，与「首次无缓存」「异常响应」分开。
- 支持 ETag / Last-Modified；304 时只更新最近成功时间，不重复插入条目。
- 失败采用指数退避（2 分钟起，最长 60 分钟），并尊重 `Retry-After`（最长 24 小时，最终受 `WB_FEED_RETRY_MAX_SECONDS` 限制）。
- 订阅条目按稳定 GUID/ID 去重，缺失时使用规范化链接，再缺失时使用标题+发布时间的稳定哈希；同一来源内去重。
- 刷新更新标题/摘要/链接，保留已读、收藏、发现时间和已有译文缓存。
- 每个订阅最多保留 500 条，优先保留最近发布/收录；收藏条目不因裁剪删除。
- 日志记录来源 ID、状态、条目数、提供方、耗时毫秒、错误类别；不记录订阅地址中的查询参数、凭据或正文。

### 出站安全

统一走 `services/public_http.py`：

- 只允许 HTTP/HTTPS 和 80/443 端口；拒绝 URL 中的账号密码。
- DNS 解析后校验所有地址均为公网地址；连接已校验的 IP，TLS 仍使用原主机名做 SNI/证书校验，避免 DNS 重绑定。
- 每次重定向重新校验目标；默认最多 5 次。
- 总超时默认 12 秒，响应体默认上限 2 MB，支持 gzip/deflate 解压后再次限制大小。
- 自定义订阅只接受公开地址；内网、回环、链路本地、云元数据地址被拒绝。
- RSS/Atom 由 `feedparser` 解析；包含 `<!ENTITY` 的 XML 直接拒绝；feedparser 不加载外部资源。
- 标题/摘要转为安全纯文本；脚本/样式标签移除；前端用 React 文本渲染，不使用 `dangerouslySetInnerHTML`。
- 订阅、条目、收藏、已读操作全部校验当前账号归属。

## 5. 配置

```env
WB_FEED_ENABLED=true
WB_FEED_DAILYHOT_BASE_URL=https://api-hot.imsyy.top
WB_FEED_GOOGLE_TRENDS_URL=https://trends.google.com/trending/rss?geo=US
WB_FEED_HOT_INTERVAL_SECONDS=900
WB_FEED_RSS_INTERVAL_SECONDS=1800
WB_FEED_SCHEDULER_INTERVAL_SECONDS=60
WB_FEED_TIMEOUT_SECONDS=12
WB_FEED_MAX_BYTES=2000000
WB_FEED_MAX_REDIRECTS=5
WB_FEED_RETRY_MAX_SECONDS=3600
WB_FEED_COMMON_ENABLED=true
WB_FEED_RUNSIGNUP_COUNTRIES=all
WB_FEED_RUNSIGNUP_CONCURRENCY=8
WB_FEED_RUNSIGNUP_INTERVAL_SECONDS=21600
WB_FEED_RUNSIGNUP_WINDOW_DAYS=90
```

`WB_FEED_ENABLED=false` 时停止后台调度，并拒绝手动刷新接口（返回 409）；已缓存的榜单和订阅条目仍可阅读，但不会发起新的外部请求。`WB_FEED_COMMON_ENABLED=false` 时只关闭日历/规则等公共源，热榜和订阅继续工作。

可选：`WB_FEED_MAX_SUBSCRIPTIONS`（默认 50）、`WB_FEED_MAX_ENTRIES`（默认 500）、`WB_FEED_TRANSLATION_BATCH`（默认 20）、`WB_FEED_TRANSLATION_CONCURRENCY`（默认 3）。

需要外网访问的域名：

- `api-hot.imsyy.top` 或自建/允许调用的 DailyHotApi 兼容实例
- 回退时：`weibo.com`、`api.zhihu.com`、`api.bilibili.com`
- `trends.google.com`
- `hnrss.org`
- `openai.com`
- 日历公共源：`runsignup.com`、`rulechannel.alibaba.com`、`rule.alibaba.com`、`h5api.m.taobao.com`、`rule.1688.com`
- 用户自行添加的 RSS/Atom 域名
- 若启用翻译：对应翻译服务域名（本次验证使用 `api.mymemory.translated.net`）

验证方式：服务器上逐个 `curl -I`/打开来源地址，再用 Nexus 页面刷新并检查来源状态、条目数和最近成功时间。浏览器端不需要直连这些域名。

- DailyHotApi 官方演示域名当前无法解析；三个国内源使用平台公开接口回退。正式运行建议配置经核验、允许调用的兼容实例。
- 只回退微博/知乎/B 站三个国内源；其他 DailyHotApi 路由未接入。
- 日历公共源已自动抓取；但 RunSignup 快照有 1000 条总上限，美国赛事会挤掉部分非美赛事，后续按国家限额优化。
- 日历的 `race_window_exceeded`/`last_error` 尚未在 UI 展示；RunSignup 全量刷新需要数分钟，前端只在 3 秒/8 秒后重取一次。
- TEMU 需要登录态、Pinterest Trends 当前网络不可达，两者只保留入口；1688 规则接口无公开文档，可能因平台改版失效。
- 翻译仅覆盖标题；正文翻译、日报和外部提醒未实现。
- MyMemory 免费服务有 500 字符/请求与配额限制；生产建议配置自建 LibreTranslate、DeepL 或已有 LLM 服务。
- 没有实时协作、评论、推送通知。
- 图片/正文摘要只保存纯文本，不抓取全文。
- 订阅上限 50、每个订阅保留 500 条；未做全文搜索。
- 多实例协调使用数据库锁；未在真实多实例集群上压测，只在代码路径和单实例运行中验证。
- 失败/恢复 UI 验收使用了数据库注入的故障状态（保留真实旧快照），随后通过真实刷新恢复；真实网络超时由自动化替身覆盖，Google 为真实失败样本。
