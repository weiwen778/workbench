# 信息聚合 · 日历看板

本文档说明 `/feeds` 第三个页签「日历」的产品结构、数据来源、接口、刷新策略和已知限制。热榜、我的订阅和标题翻译仍见 [`信息聚合.md`](./信息聚合.md)。

入口：侧栏「信息聚合」→ `/feeds?tab=calendar`。旧链接 `?tab=sources` 会自动显示为「日历」。

## 1. 页面结构

同一页固定 5 个区块，不是 5 个独立页面：

```text
┌──────────────────────────────┬────────────────────┐
│                              │                    │
│  日历                        │  数据 1            │
│  RunSignup 赛事 + 美国节日    │  订阅文章           │
│                              │                    │
├───────────────┬──────────────┼────────────────────┤
│ 数据 2        │ 数据 3       │ 数据 4             │
│ 阿里国际站规则 │ 1688 规则    │ 常用平台入口        │
└───────────────┴──────────────┴────────────────────┘
```

- 桌面端：CSS Grid，日历跨两列，右上为数据 1，底部三块并排。
- 窄屏（小于 `md`）：单列纵向堆叠，日历显示完整 6 周，数据栏固定高度并在内部滚动，避免互相覆盖。
- 每个数据栏有独立刷新按钮；数据 4 的按钮是「刷新全部」。
- 页面先读缓存，再展示刷新状态；刷新失败时保留旧条目，并显示错误提示。

## 2. 五个区块

### 2.1 日历

只放两类内容：

| 内容 | 来源 | 说明 |
| --- | --- | --- |
| 赛事 | RunSignup 公开赛事查询 | 默认查询全部国家，美国按 51 个州分别查询；每条显示国家、城市、距离和原文链接 |
| 节日 | 本地计算的美国联邦假日 | 11 个联邦假日；周六提前到周五、周日顺延到周一显示 |

日历行为：

- 周一为每周第一天，固定渲染 6 周（42 天）。
- 支持上月、下月、「今」；相邻月份日期置灰。
- 每个日期格最多显示 2 条，其余显示 `+N`；点击日期打开当天完整列表。
- 日期只在前后端之间传递 `YYYY-MM-DD`，不做 UTC 时区换算。
- 查询范围最大 62 天；前端按 42 天请求。
- RunSignup 只同步未来 `WB_FEED_RUNSIGNUP_WINDOW_DAYS` 天（默认 90 天）。

### 2.2 数据 1 · 订阅文章

- 取当前用户最近 30 条订阅条目，未读优先，组内按发布时间倒序。
- 显示标题、来源、相对时间、未读圆点；点击标题打开原文。
- 「查看全部」跳到「我的订阅」页签。
- 不在这里改变已读/收藏状态，避免与订阅页的状态管理重复。

### 2.3 数据 2 · 阿里国际站规则

- 来源：Alibaba 规则中心公开 JSON，无需登录。
- 接口：`/rulechannel/newrule/rule/latest?terminal=PC&pageIndex=1&pageSize=10&language=zh_CN`。
- 结果已按 `modifiedTime` 倒序返回；取最近 10 条，显示分类、标题、修改时间。
- 详情链接：`https://rule.alibaba.com/rule/detail/{ruleId}.htm`。

### 2.4 数据 3 · 1688 规则

- 来源：1688 规则中心 mtop 公开接口，无需登录。
- 先请求 `h5api.m.taobao.com` 获取 `_m_h5_tk` 和 `_m_h5_tk_enc` 两个 Cookie，再按 `md5(token&t&appKey&data)` 生成 `sign`。
- 请求参数必须完整：

```json
{"pageIndex":1,"pageSize":10,"lastCategoryId":null,"parentCategoryId":null,"identityCode":"4","terminal":"PC","buCode":333}
```

- 取最近 10 条，显示分类、标题、修改时间。
- 详情链接：`https://rule.1688.com/?type=detail&ruleId={ruleId}&cId={categoryId}#/rule/detail?ruleId={ruleId}&cId={categoryId}`。
- 该接口没有公开文档，可能因平台改版或风控失效；失败时保留上次成功数据并显示错误。

### 2.5 数据 4 · 常用平台入口

| 入口 | 标记 | 说明 |
| --- | --- | --- |
| TEMU 卖家中心 | 需登录 | 公告/活动需要登录态，Nexus 不代填账号、不保存 Cookie |
| Pinterest Trends | 官方入口 | 当前部署网络不可达时，只在浏览器打开入口 |
| RunSignup 赛事查询 | 官方入口 | 需要按地点/关键词筛选时打开原站 |

右上角「刷新全部」会并行触发：订阅刷新、阿里规则、1688 规则、RunSignup 赛事。

## 3. 后端设计

### 3.1 存储

不新增数据表，复用 `feed_snapshots`：

| `source_id` | 内容 |
| --- | --- |
| `common:runsignup` | 全球赛事快照 |
| `common:alibaba-rules` | 阿里规则快照 |
| `common:1688-rules` | 1688 规则快照 |

复用字段：`entries`、`provider`、`provider_note`、`last_attempt_at`、`last_success_at`、`last_error`、`error_code`、`consecutive_failures`、`next_attempt_at`、`locked_until`。

- 成功：替换快照，清空错误和锁，写 `next_attempt_at = now + interval`。
- 失败：不覆盖最近成功快照，记录错误、失败次数和退避时间。
- 成功但解析出 0 条：按失败处理（`EMPTY_PAYLOAD`），避免把旧数据清空。
- RunSignup 全部国家/州都失败：按失败处理（`ALL_COUNTRIES_FAILED`），保留旧快照。
- 手动刷新有 60 秒冷却；同一进程内并发请求会合并。

### 3.2 刷新调度

- 沿用现有 `refresh_loop`，随 Nexus `lifespan` 启停，不引入 APScheduler。
- 公共源到期后由 `refresh_due_all` 触发。
- 默认周期：阿里规则/1688 规则 3600 秒；RunSignup 21600 秒；调度巡检 60 秒。
- RunSignup 配置为 `all` 时覆盖 250 个国家和地区；美国不按国家查，而是按 51 个州分别查询，因此一次刷新约 300 个请求。并发数默认 8，抓取锁默认 600 秒。
- 所有出站请求走 `public_http.fetch_public`：只连已校验公网 IP、12 秒超时、2 MB 上限、每次重定向重新校验。

### 3.3 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/feeds/calendar?start=YYYY-MM-DD&end=YYYY-MM-DD` | 日历事件；范围最大 62 天 |
| GET | `/api/v1/feeds/data-panels` | 订阅文章、两组规则、入口 |
| POST | `/api/v1/feeds/common/{key}/refresh` | 刷新单个公共源；key 为 `runsignup`、`alibaba-rules`、`1688-rules` |
| GET | `/api/v1/feeds/common` | 兼容旧页面：返回入口分组、说明和公共源快照 |

`GET /feeds/calendar` 返回：

```json
{
  "start": "2026-11-01",
  "end": "2026-12-12",
  "events": [
    {
      "kind": "race",
      "date": "2026-11-15",
      "title": "City Turkey Trot",
      "url": "https://runsignup.com/Race/...",
      "country": "US",
      "city": "Boston, MA",
      "distance": "5K"
    },
    {
      "kind": "holiday",
      "date": "2026-11-26",
      "title": "感恩节",
      "url": "https://www.timeanddate.com/holidays/us/thanksgiving-day"
    }
  ],
  "status": "ok",
  "last_success_at": "2026-11-15T00:00:00Z",
  "last_error": null,
  "race_window_exceeded": false
}
```

`GET /feeds/data-panels` 返回：

```json
{
  "subscriptions": {"items": [], "total": 0, "unread": 0},
  "rules": [
    {"key": "alibaba-rules", "title": "阿里国际站规则", "entries": [], "status": "ok"},
    {"key": "1688-rules", "title": "1688 规则", "entries": [], "status": "ok"}
  ],
  "links": [
    {"key": "temu-seller", "title": "TEMU 卖家中心", "url": "https://...", "badge": "需登录"}
  ]
}
```

`POST /feeds/common/{key}/refresh` 返回：

- `{"queued": true}`：已排入后台刷新。
- `{"queued": false, "reason": "cooldown", "retry_after": 42}`：60 秒冷却中。
- `{"queued": false, "reason": "joined"}`：已有同源请求在执行。
- `409 FEED_DISABLED`：信息聚合或公共源功能关闭。
- `404 UNKNOWN_COMMON_SOURCE`：未知来源。

### 3.4 配置

```env
WB_FEED_COMMON_ENABLED=true
WB_FEED_RUNSIGNUP_COUNTRIES=all
WB_FEED_RUNSIGNUP_CONCURRENCY=8
WB_FEED_RUNSIGNUP_INTERVAL_SECONDS=21600
WB_FEED_RUNSIGNUP_WINDOW_DAYS=90
```

`WB_FEED_COMMON_ENABLED=false` 时，公共源刷新接口返回 409，日历返回空事件和 `status: "disabled"`；热榜和订阅不受影响。

## 6. 已知限制

- RunSignup 合并已改为每个国家最多保留 30 条，并在该国的日期范围内均匀取样；单国赛事很多时仍会看不全，但不会再被美国数据挤掉其他国家。
- ~~日历的 `race_window_exceeded`、`last_error`、`last_success_at` 未接到 UI~~ → **2026-11-15 已接入**：日历副标题显示「最近抓取 X 分钟前（具体时间）」，超出 90 天窗口显示 info 提示，抓取失败显示 warning「上次抓取失败：…（当前显示最近一次成功的数据）」。日历操作按钮补齐 `aria-label`（上月/今天/下月/刷新赛事）。
- ~~刷新后固定 3 秒/8 秒两次重取~~ → **2026-11-15 改为状态轮询**：以后端 `status === 'refreshing'` 为准，每 3 秒重取一次，连续 4 秒无刷新态或累计 180 秒后停止。
- ~~`refresh_due_all` 同步执行 RunSignup 抓取~~ → **2026-11-15 已拆出**：规则源同步刷新，RunSignup 走守护线程 `feeds-runsignup`，单飞（`_reserve`）保证不重入，不再阻塞热榜/订阅调度。
- 节日只做美国 11 个联邦假日，不做州/地方节日，也不做其他国家节日。
- 1688 mtop 接口无公开文档，存在平台改版或风控导致失效的风险。
- TEMU 需要登录态，Pinterest Trends 在当前部署网络不可达；两者只保留入口，不抓取内容。
- 赛事标题保留英文，不做自动翻译。
- 订阅文章只展示标题和摘要，不抓取正文；正文阅读器不在本功能范围。
- 热榜和订阅页仍各自使用原有布局，本次未合并为同一套组件。
- ~~公共源刷新只做 60 秒统一冷却~~ → **2026-11-15 已分离**：规则源仍为 60 秒，RunSignup 使用 `WB_FEED_RUNSIGNUP_COOLDOWN_SECONDS`（默认 600 秒），快照锁同样按该值延长；前端冷却提示按后端 `retry_after` 展示。
- ~~`GET /feeds/common` 返回公共源完整快照~~ → **2026-11-15 已裁剪**：`common_payload(include_races=False)`，兼容接口与 `/feeds/data-panels` 都不再传输 RunSignup 赛事条目，赛事统一由 `/feeds/calendar` 提供。
