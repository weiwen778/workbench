# 打卡并入待办设计（方案 3：周期待办替代打卡）

日期：2026-11-21
状态：待确认
范围：`server/`、`web-react/`、一次性迁移脚本

## 1. 意图

打卡与待办在“每天出现一组要勾选的事项”这件事上高度重合。用户选择用**周期待办**替代打卡，旧打卡数据保留为**只读归档**。

目标不是把打卡页面塞进待办，而是让待办成为唯一的任务模块：日常、周常、月常事项都在待办里生成、完成和查看。

## 2. 现状

- 打卡：9 个对象（6 店铺 + 3 社媒）、4 个分组、48 条规则（45 条启用）、10,230 条历史实例。按日/周/月自动生成实例，支持完成、取消、备注、历史、统计、置顶、导入。
- 待办：4 个清单（年度经营项目、活动与上新、异常跟进、本周行动）、263 条任务，支持子任务、截止日期/时间、手动/自动排序、已完成折叠。
- 打卡是当前默认首页：`/`、`/login` 都落到 `/checkins`；侧栏「打卡」是一个一级模块，9 个对象作为二级项。
- 打卡与多个外围功能有耦合：偏好里的门店/社媒标签、Agent 的 `checkins` 模块、打卡导入、工作目标接口、相关测试。

两者相似在“清单 + 勾选”，不同在：打卡每个周期生成独立实例并锁定历史；待办是长期存在的任务，且有子任务和截止时间。

## 3. 目标与非目标

### 目标

1. 待办支持日/周/月重复任务，能替代日常打卡清单。
2. 侧栏移除「打卡」，默认首页改为待办。
3. 45 条启用的打卡规则迁移为一个「日常打卡」清单里的周期任务，日常事项不丢失。
4. 10,230 条旧打卡历史保留，提供只读查询页面。
5. 旧打卡数据不删除、不做不可逆改写；需要时可以回滚。

### 非目标

- 不保留打卡的目标管理、分组管理、置顶、进度环、周期筛选明细、打卡备注弹层、Excel 导入。
- 不把 10,230 条历史实例迁移成待办；它们只作为归档查询。
- 不保留打卡的写接口；旧接口只保留必要的只读查询。
- 不在 v1 支持复杂的重复规则（如“每周一三五”“每月最后一个工作日”）。
- 不保证 Agent 能通过旧 `checkins` 权限继续写打卡；旧权限写操作退役。

## 4. 方案与选择

### A. 只合并入口

保留打卡引擎，只在待办页面增加一个「打卡」入口。

- 优点：改动小、风险低、历史与统计完全不变。
- 缺点：底层仍是两套任务模型，用户感知的“重复模块”没有真正消失。

### B. 打卡实例迁移成待办

把对象、规则、实例都映射成待办清单和任务，统一到一套表。

- 优点：只有一套数据。
- 缺点：10,230 条实例迁移成本高，打卡的周期锁定、改周期生效规则与待办语义冲突，迁移后很难验证。

### C. 周期待办替代打卡（选择）

新增重复任务能力，迁移当前启用的规则；旧历史归档只读。

- 优点：真正只保留一套任务；新数据简单；旧数据不动，可回滚。
- 缺点：放弃打卡的部分专属能力；历史与新的周期任务不是同一种记录。

**选择 C。** 先接受“历史是历史、新任务是新任务”，避免为了统一而做高风险的大迁移。

## 5. 设计

### 5.1 数据模型

在 `todos` 表新增：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `repeat` | `String(16)`，默认 `none` | `none` / `daily` / `weekly` / `monthly` |
| `repeat_anchor_day` | `Integer`，可空 | 月重复的原始日号（1–31）；短月夹取后仍回到原日号 |
| `repeat_from_id` | `Integer`，可空，`FK todos.id ON DELETE SET NULL` | 本次任务由哪一次完成生成，用于历史和排查 |

新增映射表 `checkin_todo_migrations`：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `rule_id` | 旧 `checkin_rules.id`，唯一 |
| `todo_id` | 新 `todos.id` |
| `created_at` | 迁移时间 |

新增待办文件夹：

`todo_folders`：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `name` | 文件夹名，唯一 |
| `sort_order` | 排序 |
| `created_at` / `updated_at` | 时间戳 |

`todo_lists` 增加：

| 字段 | 说明 |
| --- | --- |
| `folder_id` | 可空，`FK todo_folders.id ON DELETE SET NULL` |

层级固定为 **文件夹 → 清单 → 任务 → 子任务**，不做无限嵌套。文件夹只装清单，不直接装任务；`folder_id` 为空的清单显示在「未分组」伪文件夹下。删除文件夹时只把清单移到「未分组」，不删除清单和任务。

约束：

- 只有顶层任务（`parent_id IS NULL`）可以设置重复；有子任务的任务不能设置重复。
- 重复任务不能再添加子任务；给重复任务加子任务的请求返回 `409`，前端隐藏该入口（否则现有“父任务由子任务决定完成”的规则会让重复链卡死）。
- `repeat != none` 时必须有 `due_date`；新建时没填日期：每天填今天，每周填本周日，每月填本月最后一天（`repeat_anchor_day = 31`）。
- 删除清单/任务进回收站时，快照必须保留 `folder_id`、`repeat`、`repeat_anchor_day`、`repeat_from_id`；恢复后重复链和所属文件夹不丢失。
- `repeat_anchor_day` 只在 `monthly` 时有值；创建/迁移时取当时 `due_date` 的日号。旧打卡月度规则迁移时固定为 31（表示“月末”）。
- 旧表 `work_targets`、`checkin_groups`、`checkin_rules`、`checkin_instances`、`checkin_rule_versions` 保留，不删除、不改写。

### 5.2 重复任务行为

- 新建/编辑任务时可选择「不重复 / 每天 / 每周 / 每月」。
- 完成一个重复任务时：
  1. 把当前任务标记完成，保留在已完成区。
  2. 在同一清单创建下一条顶层任务，复制标题、备注、`repeat`、`repeat_anchor_day`、截止时间；`repeat_from_id` 指向刚完成的任务。
  3. 下一条的 `due_date` 按周期推进：每天 +1 天；每周 +7 天；每月取下一个月的 `repeat_anchor_day`，该日不存在时取当月最后一天（例如 1/31 → 2/28 → **3/31**，不会漂移到 28 号）。
  4. 如果结果仍在今天或之前，继续加周期直到晚于今天（不补历史欠账）。
- 截止日期的含义：日报是“今天”，周报/月报是“本周期最后一天”。迁移时周任务落在本周日、月任务落在本月最后一天，所以周任务不会在周二就变红；周期结束后未完成才显示逾期。
- 重复任务被取消完成时：
  - 只允许在下一周期尚未真正开始时撤销：下一条任务存在、未完成、无子任务、`version == 1`，则删除下一条；
  - 否则返回 `409`「下一周期已经开始，不能撤销本次完成」。
  - 为保证 `version` 能代表“被改过”，移动清单和手动排序也会递增 `version`。
- 删除当前未完成任务：停止后续生成。
- 修改重复周期：只影响当前任务和之后生成的任务；已完成的历史不动。
- 移动清单：之后生成的任务跟随新清单。
- 排序：新生成任务按当前清单最大 `sort_index + 1`；自动排序时仍按截止日期展示。

### 5.3 迁移

新增一次性脚本 `scripts/migrate_checkins_to_todos.py`：

- 默认 `--dry-run`，只打印将创建/跳过的内容；`--apply` 才写库。
- 在事务内执行，失败整体回滚。
- 步骤：
  1. 找到或创建文件夹「日常」「经营」「内容」「复盘」；把现有清单归位：日常 → 本周行动，经营 → 年度经营项目、异常跟进，内容 → 活动与上新。只在 `folder_id` 为空时归位，不覆盖用户后来手动移动的结果。
  2. 找到或创建清单「日常打卡」，放进「日常」文件夹，排序排最前，使它成为 `/todos` 的默认清单。
  3. 对每条 `CheckinRule.active == true` **且** `WorkTarget.status == 'active'` 的规则：如果 `rule_id` 没有迁移记录，创建待办：
     - 标题：`对象名 · 规则标题`，例如「天猫旗舰店 · 昨日经营数据核对」。
     - 备注：规则说明；若原规则有分组，追加一行「分组：经营数据」。
     - `repeat`：`daily` / `weekly` / `monthly`。
     - `due_date`：当天 / 本周日 / 本月最后一天。
     - `repeat_anchor_day`：月重复填 31（月末）；日/周重复为空。
     - `repeat_from_id`：空。
     - 周期使用当前生效的 `period`；`pending_period` 作为未生效计划忽略（迁移报告里列出，之后可在待办里手动改）。
  4. 写入 `checkin_todo_migrations`。
  5. 不生成历史实例，不修改旧表。
- 结果预期：当前 45 条启用规则且对象均 active，迁移为 45 条待办 + 45 条映射；若存在已归档对象，实际条数会少于此数，dry-run 报告以实际查询为准。重复执行不新增。
- 生产执行前先备份数据库；执行后核对数量与旧历史总数（10,230 不变）。

### 5.4 导航、文件夹与待办界面

#### 导航

- 移除侧栏一级项「打卡」；APP_NAV、MODULE_KEYS、AppRail 分类、预加载中的 checkin 项一起移除。
- `/`、`/today`、`/tasks`、`/search`、`/activity`、`/checkins`、`/checkins/*` 全部重定向到 `/todos`；登录默认跳 `/todos`。
- 全局侧栏的待办二级项继续用**平铺清单**做快速切换（不加文件夹标题），现有 4 个清单 +「日常打卡」= 5 项，按 4 项 +「更多」规则展示，当前清单始终可见。文件夹只在待办页内的左栏出现，避免侧栏出现三级结构。
- 「日常打卡」按文件夹/清单顺序排在第一位，`/todos` 打开它，保持“打开工作台先看今天要做的事”的习惯。
- 旧打卡页面、目标详情、导入入口全部移除；`/checkins/targets/*` 也重定向到 `/todos`。

#### 迁移后的默认文件夹

| 文件夹 | 清单 |
| --- | --- |
| 日常 | 日常打卡、本周行动 |
| 经营 | 年度经营项目、异常跟进 |
| 内容 | 活动与上新 |
| 复盘 | （空，留给后续复盘清单） |
| 未分组 | `folder_id` 为空的清单，伪文件夹，不落库 |

#### 页面结构

桌面端为两栏，左栏 240px 文件夹/清单树，右栏任务区：

```text
┌ 文件夹 / 清单 ─────────┐  ┌ 日常 / 日常打卡        42 项 ┐
│ 文件夹 +               │  │ [今天] [本周] [全部]         │
│ ▾ 日常            18   │  │ 逾期 2                       │
│    日常打卡       12   │  │  ☐ 昨日经营数据核对  ↻ 每天  │
│    本周行动        6   │  │  ☐ 补录退款原因              │
│ ▸ 经营            31   │  │ 今天 5                       │
│ ▸ 内容             9   │  │  ☐ 库存异常跟进  ↻ 每周      │
│ ▸ 复盘             0   │  │ 以后 / 无日期                │
│ 未分组              3   │  │ 已完成（折叠）               │
└────────────────────────┘  └──────────────────────────────┘
```

#### 左栏：文件夹/清单树

- 文件夹行：展开/收起箭头、名称、待办数、更多菜单。
- 文件夹菜单：新建清单、重命名、删除、上移、下移。
- 删除文件夹：只把清单移到「未分组」，不删除清单和任务；确认框明确说明。
- 清单行：名称、未完成数量；选中高亮；点击切换右侧任务区。
- 清单菜单：重命名、移动到文件夹、删除、排序模式（自动/手动）、上移、下移。
- 数量口径统一为**未完成的顶层任务**，不含子任务，不含已完成；文件夹数量为其清单数量之和。
- 排序：文件夹按 `sort_order`；清单全局只有一个 `sort_order`，在文件夹内按它排序。移动到新文件夹时排到该文件夹末尾；上移/下移交换相邻清单的 `sort_order`。
- 底部「新建文件夹」；文件夹内提供「新建清单」。
- 展开状态按用户存 `localStorage`，刷新后保持。
- v1 用菜单移动和上移/下移排序；文件夹/清单拖动排序不在本轮范围。

#### 右栏：任务区

- 顶部：`文件夹 / 清单` 面包屑、清单名、未完成/总数、排序切换、刷新、更多。
- 筛选 chips：**今天 / 本周 / 全部**，默认「今天」。
  - 今天：逾期 + 今天到期 + 无日期任务；本周：逾期 + 本周内到期 + 无日期；全部：所有未完成。
- 分组只在**自动排序**下出现：逾期、今天、以后、无日期；每组显示数量。手动排序时是平铺列表，不显示日期分组，拖动只在当前平铺顺序内调整，不通过拖动改截止日期。
- 快速添加行：标题输入、重复选择（不重复/每天/每周/每月）、截止日期、添加按钮；窄屏自动换行。
- 新建重复任务但没选截止日期时：每天 = 今天；每周 = 本周日；每月 = 本月最后一天（`repeat_anchor_day = 31`），与迁移任务的含义一致。
- 任务行：勾选框、标题、重复标记、截止时间、子任务进度、备注图标、拖动排序、更多菜单。
- 重复任务显示「每天/每周/每月」标记；完成后续周期自动出现。
- 头部「未完成/总数」与分组数量都按**顶层任务**统计；子任务进度只在任务行显示。
- 已完成区折叠在底部，显示完成时间；只显示当前清单最近完成的 50 条，独立分页/加载更多，不随今天/本周 chip 过滤。重复任务的已完成记录保留重复标记。
- 从全局搜索跳转 `?focus=<id>` 时，筛选自动切到「全部」；如果目标任务已完成，自动展开已完成区并滚动到它。
- 空态按筛选区分：今天没有任务、本周没有任务、全部没有任务。
- 所有间距沿用全局 10px 内容间距。

#### 移动端

- 左栏收进抽屉，任务区顶部显示「文件夹」按钮。
- 筛选 chips 横向可滚动，不换行撑破页面。
- 任务行操作保持 44px 以上点击区域；重复/截止信息不挤压标题。

#### 接口

- `GET /api/v1/todo-folders`：返回文件夹及清单（或与 `todo-lists` 合并返回 `folder_id`）。
- `POST /api/v1/todo-folders`：新建文件夹。
- `PATCH /api/v1/todo-folders/{id}`：重命名、排序。
- `DELETE /api/v1/todo-folders/{id}`：删除文件夹，清单 `folder_id` 置空。
- `POST /api/v1/todo-lists`、`PATCH /api/v1/todo-lists/{id}`：支持 `folder_id`、`sort_order`、`sort_mode`。
- `GET /api/v1/todo-lists` 返回 `folder_id` 和按 `(folder.sort_order, list.sort_order)` 排好的顺序；前端按文件夹分组，全局侧栏直接使用这个顺序平铺。
- `GET /api/v1/todos`：未完成列表用于前端分组，当前清单的顶层未完成任务一次性返回（超过 500 条时分批加载）；返回的 `counts`、`pending` 统计改为**顶层任务**口径；已完成仍用 `completed_page` 分页，最近 50 条。
- `?focus=<id>` 仍由后端定位所在页，前端收到 focus 后切「全部」并展开已完成。

### 5.5 只读历史归档

新增只读页面 `/todos/checkin-history`，入口放在待办页面的全局工具栏（不依赖「日常打卡」清单是否存在），同时在「日常打卡」清单的更多菜单里提供一个快捷入口。

- 筛选：对象、分组、周期（日/周/月）、状态（已完成/未完成）、关键词。
- 列表列：周期开始-结束、对象、分组、事项、状态、完成时间、备注。
- 分页，不提供任何写操作。
- 数据来源只使用新增的纯读接口 `GET /api/v1/checkin-history`：只做 SELECT，不调用 `ensure_target_period`，也不刷新锁状态。筛选下拉的对象/分组从归档记录去重得到。
- 顶部汇总使用同一纯读接口返回的汇总；不调用会生成实例的 `/checkin-instances` 或 `/work-targets/{id}/rules`。
- 旧写接口统一返回 `410 Gone`，提示「打卡已合并到待办，历史记录只读」：
  - `/checkin-instances/*` 的 complete、cancel、PATCH；
  - `/work-targets/*` 的新建、修改、删除、归档、恢复；
  - `/checkin-groups/*` 的新建、修改、删除；
  - `/checkin-rules/*` 的新建、修改、删除、导入；
  - 打卡导入接口。
  这些接口里任何会调用 `ensure_target_period` 的写路径都必须停用，保证归档不再增长。
- 历史上由导入创建的实例仍在归档里；系统没有独立的“导入记录”表，因此不额外展示导入审计。
- 保留的 GET 只做纯查询：新增 `/api/v1/checkin-history` 不调用生成逻辑；旧 `/checkin-instances/history` 若保留，也去掉刷新锁/生成副作用。
- 旧 `work_targets` / `checkin_rules` 只读保留，供归档筛选使用。

「日常打卡」是一个普通待办清单，可以重命名或删除；删除只影响清单里的待办，不影响 `/todos/checkin-history` 的旧历史。

### 5.6 偏好、Agent 与外围

- 偏好中的 `checkin_shop_label` / `checkin_social_label` 停止展示；字段保留，避免迁移用户数据。
- Agent：
  - 从**新令牌**的可写模块中移除 `checkins`；新令牌不再提供打卡写权限。
  - 旧令牌若已有 `checkins` 权限，只保留对旧只读接口的访问，不能写；新归档页按待办模块权限 `todos:read` 授权。
  - 更新 Agent 指南中的模块列表与“打卡暂不支持撤销”等描述。
- 删除或停用打卡相关的快捷入口、默认页标题、预加载与测试断言。

## 6. 边界与错误处理

- 月重复日期不存在：落到当月最后一天。
- 跨时区：沿用现有 `Asia/Shanghai` 本地日期逻辑，不引入 UTC 日期漂移。
- 重复任务带子任务：禁止设置重复，前端提示先移除子任务。
- 同时完成两次：后端以版本号/幂等检查保证只生成一条下期任务。
- 下期任务已存在：不重复创建。
- 迁移中断：事务回滚；映射表保证重跑幂等。
- 旧历史为空：归档页显示空态，不报错。

## 7. 发布与回滚

发布顺序：

1. 备份生产数据库。
2. 部署后端迁移（新增字段/表）+ 前端。
3. 运行 `migrate_checkins_to_todos.py --dry-run`，核对 45 条。
4. `--apply`，核对新清单、任务数、映射数、旧历史数。
5. 验证 `/todos` 默认打开「日常打卡」，旧 `/checkins` 正确重定向，归档页可查。

回滚：

- 应用回滚到上一版镜像。
- 删除迁移创建的「日常打卡」清单及其任务（通过 `checkin_todo_migrations` 精确定位）。
- 删除映射表与新增字段（或保留字段但不再使用，优先保留以避免二次迁移）。
- 旧打卡数据从未修改，恢复旧版本即可继续使用。
- 生产数据库备份保留到确认稳定。

## 9. 已做的决定（待确认）

1. 只建一个「日常打卡」清单，不按对象/分组拆成 9 个或 4 个清单；对象名放进任务标题，分组名放进备注。理由：避免侧栏二级项膨胀。
2. 迁移启用规则（`rule.active` 且对象 `active`），而不是从空清单开始。理由：日常事项不能丢。
3. 旧历史用独立只读页 `/todos/checkin-history`，不混进待办列表。理由：历史是周期实例，和待办任务语义不同。
4. 不做 10,230 条实例到待办的迁移。理由：成本高、收益低、难以验证。
5. 重复任务采用“完成即生成下一条”的单条链，不预生成未来周期。理由：避免积压和重复完成。
6. 周/月任务的截止时间取周期最后一天，而不是周期第一天；避免周任务在周二就显示逾期。月重复用 `repeat_anchor_day` 保留原日号，短月夹取后回到原日号。
7. 「日常打卡」是普通清单，可重命名/删除；历史归档入口在待办全局工具栏，不依赖该清单存在。
8. 重复任务禁止子任务；取消完成只删除“未开始且未修改”的下一条，否则拒绝。
9. 迁移忽略 `pending_period` 未来计划，使用当前生效周期，并在迁移报告中列出。
10. 旧打卡导出的实例留在归档里；没有独立导入记录表，不新增导入审计。
11. 待办层级固定为「文件夹 → 清单 → 任务 → 子任务」，不做无限嵌套；文件夹只装清单，不直接装任务。
12. 全局侧栏继续平铺清单做快速切换，文件夹树只在待办页左栏出现，避免侧栏三级结构。
13. 删除文件夹只把清单移到「未分组」，不删除清单和任务。
14. v1 用菜单移动清单和上移/下移排序，不做文件夹/清单拖拽。
15. 自动排序才显示逾期/今天/以后/无日期分组；手动排序是平铺列表，拖动不改截止日期。
16. 计数统一为未完成的顶层任务，子任务不计入清单/文件夹/头部/分组数量；已完成区独立显示最近 50 条，不随筛选 chip 变化。
17. 列表顺序使用单一 `sort_order`，按 `(folder.sort_order, list.sort_order)` 展示；移到新文件夹时排到末尾。
18. 回收站快照保留 `folder_id` 与重复字段，恢复后不丢文件夹、不把重复任务变成一次性任务。
19. 新建周/月重复未填日期时，分别填本周日和本月最后一天；不填今天。
20. `?focus=` 跳转覆盖默认「今天」，切到「全部」并在需要时展开已完成。
21. 打卡的目标、分组、规则、实例写接口和导入全部退役并返回 410；只保留纯读归档接口。
