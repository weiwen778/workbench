# 看板配置默认值修正（P0）设计

日期：2026-11-19
状态：已完成（2026-11-20）

## 背景

可用性诊断（`/tmp/opencode/uploads/a901c2c6614848/board-usability.md`）指出：看板的配置成本不只来自字段数量，更来自默认值会直接产出错误结论。本次只处理其中三条数据正确性问题，不动视觉间距与交互重构。

## 目标

1. 时间分组的柱状图不再按数值排序，旧图表也纠正。
2. 饼图新建时默认选低基数维度，并提示高基数列与分组过多。
3. 任务进度不再自动挑选“完成条件”，必须用户显式选择。

## 非目标

- label 压线与字段间距（报告第 2 节）；需在实际构建上复现后单独处理。
- 配置弹窗向导化、卡片尺寸调整、时间筛选统一入口（报告 P1）。
- 修改已有饼图的用户配置。
- 数据库迁移。

## 方案

### 1. 时间分组排序

后端 `server/app/services/dashboard.py`：

- 单系列：`bar` 与 `line` 一致，分组列为日期时按标签升序，并取最近 `limit` 组。
- 多系列：`aggregate` 的截断逻辑对 `bar` 与 `line` 一致使用 `points[-limit:]`。
- 不再保留“日期分组 + value_desc”的后端出口；以后需要“销售额最高的 N 天”时再新增显式排序枚举。

前端 `web-react/src/pages/Dashboard.tsx`：

- 新建/切换分组时，日期列自动设 `sort: 'label_asc'`。
- 分组列为日期时隐藏“横轴项目怎么排列”下拉，与折线图现有行为一致。

### 2. 饼图默认分组

前端 `Dashboard.tsx`：

- 新增默认分组选择函数：取表格列顺序中的第一个非日期维度；只有全部维度都是日期时才回退到日期列。
  （没有采用“勾选列优先”：勾选列常是「已核对」这类操作标记，用它做占比没有业务意义。）
- `chooseTable` 与切到饼图时使用该函数；若当前分组是日期列且切到饼图，则替换为推荐分组。
- 分组下拉中标注：日期列「（时间列，不适合占比）」；选项数 >12 的单选列「（选项较多，不适合占比）」。
- 预览 `groups_total > 8` 时显示提示「分组过多，建议改用柱状图」，提供一键切到柱状图。

### 3. 任务进度完成条件

前端：

- `emptyProgress()` 的 `completed` 改为 `null`。
- `initializeProgress()` 不再自动挑完成条件；数值累计模式仍自动带出完成量/目标列。
- `ProgressEditor` 在任务模式下始终渲染「哪些记录算完成？」，未选择时显示空条件行与必填提示。
- 完成条件字段按「勾选 → 单选 → 文本」排序；选择文本列时提示确认该列含义。
- 表格没有勾选/单选列时提示「当前表格没有状态列，建议改用数值累计」。
- `previewReady` 与保存按钮增加进度配置完整性判断；未选完成条件时不能预览/保存。

后端：`Widget` 已要求任务模式必须有 `completed`，无需改动。

## 测试

- 后端新增：日期分组柱状图默认按时间升序、limit 取最近 N 组。
- 后端回归：现有柱状图/折线图/多系列/饼图用例。
- 前端：`npm run typecheck`；人工验收新建饼图、任务进度、旧图表排序。
