# 表格渲染性能优化 · 设计

日期：2026-11-20
状态：已完成（2026-11-20，随整理提交合并）
范围：`web-react/src/components/TableView.tsx`、`web-react/src/ui/common.tsx`，以及性能回归脚本

## 为什么改

表格是高频使用页面。120 行、41 列、4 倍 CPU 降速下：

- 勾选一行：中位 142ms、P95 148ms，用户能明显感到「卡一下」。
- 横向滚动：75 帧里 17 帧 >25ms，2 个长任务，最长 54ms。
- 双击编辑：DOM 层约 4ms，但会触发同样的全表重渲染。

CPU profile 显示，点选时最大自耗时来自 emotion 的样式序列化（`getThemeValue`、`serializeStyles`、`handleInterpolation`、`murmur2`、`deepmerge`），其次是每个单元格的一次 React 元素创建。原因是：

1. `TableView` 的选择状态变化会让 `DataTable` 重新生成整套 `columns`。
2. 每个单元格都用 MUI `Box` + 内联 `sx`，每次重渲染都重新计算样式。
3. `DataTable` 的 `getRowId` 和 `renderCell` 里用 `rows.indexOf(row)`，是 O(行数)。
4. 自定义 `__select` 列把选择状态直接编进列定义，导致选择变化必然重建列。

## 目标

- 勾选、取消勾选不再触发整页单元格重渲染；点选中位降到 90ms 以内（4 倍降速基线，实测 77.6ms）。
- 横向滚动 >25ms 的帧从 19 降到 15 以内，>50ms 的帧基本为 0（偶发 1 帧）；残余主要是 MUI 虚拟滚动条自身的工作。
- 双击打开编辑器不再重建整表列定义；编辑器中位从 130.4ms 降到 80ms 以内（实测 19.1ms），输入时只更新当前单元格。
- 单元格长文本不溢出，窄屏工具栏/筛选栏不把页面撑出横向滚动。
- 行为保持不变：当前页全选、跨页保留选择、批量删除上限 100 行、固定左侧日期/店铺列、右侧操作列。

## 非目标

- 不改服务端分页、筛选、排序接口。
- 不改表格数据结构、字段类型或工作簿（Univer）路径。
- 不替换 MUI DataGrid，不做自研虚拟表格。
- 不调整表格的视觉风格（行高、斑马纹、居中设置保持不变）。

## 反目标

- 为了性能牺牲双击编辑、跨页选择或固定列行为。
- 用 `memo` 掩盖问题但列定义仍在每次渲染时变化。
- 把样式全部搬进全局 CSS 后失去主题切换（明暗色）能力。

## 方案比较

### A. 保留 DataGrid，削减单元格成本 + 稳定列定义 + 内置选择（已选）

1. 单元格内容改为普通 `span` + 一个 CSS class，去掉每格 `Box`/`sx`。
2. `TableView` 的列定义用 `useMemo` 稳定化，选择状态不再进入列定义。
3. 选择改用 DataGrid 内置 `checkboxSelection` + `rowSelectionModel`，勾选只更新受影响的行。
4. `getRowId` / 单元格渲染改用 id/index Map，去掉 `rows.indexOf`。

优点：改动集中在两个文件，保留现有交互和固定列逻辑；预计点选 142ms → 30–50ms。
缺点：编辑状态仍在列定义闭包里，编辑开始/结束会重建一次列；但单元格渲染已变轻，代价可接受。

### B. 只做单元格轻量化和 indexOf 修复

优点：风险最低。
缺点：选择变化仍会重建整个 columns、重渲染当前页全部单元格，预计只能降到 70–100ms，不解决「点选卡一下」的根因。

### C. 替换 DataGrid 为自研虚拟表格

优点：性能上限最高。
缺点：重写固定列、列宽、排序、选择、虚拟化、可访问性和主题适配，回归成本远大于收益，且当前瓶颈不在 DataGrid 的虚拟化本身。

选择 A。B 不足以解决根因，C 与本次目标不匹配。

## 实现设计

### 1. DataTable 新增选择能力

`web-react/src/ui/common.tsx` 增加可选 props：

- `checkboxSelection?: boolean`
- `rowSelectionModel?: (string | number)[]`
- `onRowSelectionModelChange?: (model: (string | number)[]) => void`

内部：

- 把 `checkboxSelectionVisibleOnly` 设为 `true`，保持「全选只选当前页」。
- 当 `checkboxSelection` 开启时，自动把内置字段 `__check__` 放到固定列最左侧。
- `gridColumns` 用 `useMemo` 缓存，依赖只包含真正影响列结构的输入（columns、列宽、居中、排序回调）。
- 建立 `WeakMap<row, index>` 或 `Map<row.id, index>`，让 `rowKey` 和 `renderCell` 不再线性查找。
- `getRowId` 用 `useCallback` 固定，返回 `String(id)`；`rowSelectionModel` 与行 id 字符串对齐。
- 把 DataGrid 的静态 `sx` 拆成稳定对象或 `useMemo`，避免选择变化时重复序列化整表样式。

### 2. TableView 列定义与单元格

- 删除自定义 `__select` 列及 `allVisibleSelected` / `someVisibleSelected` / `toggleVisibleSelection`。
- `selection` 仍以 `number[]` 保存在 TableView，由 `rowSelectionModel` 的字符串数组映射而来，批量删除逻辑不变。
- 列数组用 `useMemo`，依赖字段、排序、编辑状态；选择状态不再参与。
- `renderCell`：
  - 文本/数字/日期/选项：`<span className="wb-table-cell-text" title=...>`，样式由 DataTable 的 `sx` 统一提供（`minWidth: 0`、`overflow: hidden`、`textOverflow: ellipsis`、`whiteSpace: nowrap`）。
  - 勾选：保留 MUI `Check` 图标和「否」文本，但不再外包 `Box`。
  - 附件/链接：保留现有行为，外层不再用带 `sx` 的 `Box`。
- `renderEditor` 保持不变；编辑开始/结束会触发一次列重建，但单元格已轻量化。
- 固定列仍按「日期 + 店铺/门店」规则，只是最左侧字段换成 `__check__`。

### 3. 溢出收口

- 单元格文本统一 `ellipsis`，数字列仍右对齐。
- 筛选条件面板加 `minWidth: 0`、`overflowX: auto`，条件多时横向滚动而不是撑破页面。
- 工具栏保持 `flexWrap`，补 `minWidth: 0`，保证窄屏换行而不是溢出。
- 不新增全局横向滚动；在 1440 / 1280 / 1024 / 800 四档宽度下断言 `scrollWidth <= innerWidth`。

## 验证

新增/完善 `e2e/table-render-performance.mjs`，作为可重复的红绿信号：

- 固定生成 120 行、10 列业务字段 + 可配置附加列（默认 30 列宽表）。
- 4 倍 CPU 降速下测量：
  - 当前页勾选 8 次，中位耗时 ≤ 90ms（基线 153.9ms，已先在基线上变红）。
  - 横向滚动 30 次，>25ms 的帧 ≤ 15（基线 19），>50ms 的帧为 0。
  - 双击打开编辑器 6 次，中位 ≤ 80ms（基线 130.4ms）。
  - 页面无横向溢出；单元格文本使用省略号。
- 每次运行结束删除临时表。
- 另跑现有 React 表格流程回归（选择、跨页全选、编辑提交/取消、批量删除、固定列、空表、200 列）与 `npm run typecheck`、`npm run build`。

## 验证结果（2026-11-20）

41 列、120 行、4 倍 CPU 降速、生产构建：

| 指标 | 基线 | 结果 |
| --- | --- | --- |
| 点选中位 | 153.9ms | 77.6ms |
| 横向滚动 >25ms 帧 | 19 | 14 |
| 横向滚动 >50ms 帧 | 1 | 0–1 |
| 双击打开编辑器中位 | 130.4ms | 19.1ms |

残余:横向滚动的主要自耗时来自 MUI 的 `GridVirtualScrollbar` 和列虚拟化，不再是单元格 renderer；继续压低需要替换滚动实现，超出本次范围。

## 留给实现者的决定

- `gridColumns` 的具体 memo 依赖列表，以实际渲染行为为准。
- 复选框列宽度是否沿用内置 50px，还是通过列定义覆盖为 42px。
- 选择模型里字符串 id 与数字 id 的转换放在 `DataTable` 还是 `TableView`；优先放在 `TableView`，保持 `DataTable` 通用。
- 编辑状态已按实测结果移出列定义：放在模块级 store，由 `TableCell` 用 `useSyncExternalStore` 订阅，双击只重渲染当前单元格。
