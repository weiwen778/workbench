# 运行日志中心与问题反馈设计

日期：2026-11-16
状态：已确认，开始实现

## 目标

1. 在设置中提供一个可随时翻查、检索运行日志的页面，覆盖后端应用日志、API 请求记录、后台任务异常和前端崩溃/接口失败。
2. 在顶栏提供一个反馈入口，把 bug 或需求提交到 GitHub Issue，自动附带环境信息和最近错误日志，失败可重试。

## 非目标

- 不采集 Nginx 访问日志、容器日志或宿主机日志。
- 第一版不支持截图/图片附件。
- 不做多用户权限体系；反馈与日志页面只对管理员开放。

## 方案

### 日志存储

PostgreSQL/SQLite 通用表 `app_logs`，Alembic 迁移建表。自定义 `logging.Handler` 把结构化记录放入有界队列，后台线程每 0.5 秒或累计 200 条批量写库；队列满时丢弃并计数，写库失败只写 stderr，绝不递归调用 logging。

- 字段：`id, created_at, level, source, logger, message, stack, path, method, status, duration_ms, request_id, user_id, context`。
- 来源：`backend`（普通 logging）、`request`（访问/异常）、`job`（后台任务）、`frontend`（浏览器上报）。
- 脱敏：password/token/secret/authorization/cookie/api_key 等键值在入库前替换为 `***`；单条消息与堆栈截断。
- 保留：维护任务按 `WB_LOG_RETENTION_DAYS`（默认 30 天）删除。
- 实时尾随：前端轮询第 1 页（2 秒），不引入 SSE，避免代理与连接管理复杂度。

### 反馈发送

服务端保存 GitHub 仓库与细粒度 PAT（Issues 读写），用现有 Fernet 加密。提交先落 `feedback_submissions`（pending → sent/failed），立即调用 GitHub REST API 创建 Issue，失败保留错误并支持重试。Issue 正文包含用户描述、应用环境、请求 ID 与日志摘要。

- 降级：设置页和反馈弹窗都提供「浏览器打开预填 GitHub 新建页」。
- 安全：仓库名做正则校验，禁止路径穿越；令牌永不回传；接口仅管理员可用。
- 标签：可配置；若 GitHub 因标签不存在返回 422，自动去掉标签重试并记录提示。

## 数据表

- `app_logs`：见上，索引 `created_at`、`(level, created_at)`、`(source, created_at)`、`request_id`。
- `feedback_integrations`：单行配置，`repo, encrypted_token, labels(JSON), enabled, last_test_ok, last_test_message, last_tested_at, updated_at`。
- `feedback_submissions`：`user_id, kind, title, body, status, issue_number, issue_url, error, attempts, log_snapshot, environment(JSON), created_at, updated_at, sent_at`。

## 接口

- `GET /api/v1/logs`：级别/来源/关键字/请求 ID/时间范围/`after_id`/分页。
- `GET /api/v1/logs/summary`：24 小时各级别计数。
- `GET /api/v1/logs/{id}`：单条详情。
- `DELETE /api/v1/logs`：清空（可带 `before`）。
- `GET /api/v1/logs/export?format=csv|json`：导出当前筛选结果。
- `POST /api/v1/logs/client`：浏览器日志上报，按用户限流并去重由前端负责。
- `GET/PUT /api/v1/feedback/config`、`POST /api/v1/feedback/config/test`。
- `POST /api/v1/feedback`、`GET /api/v1/feedback`、`POST /api/v1/feedback/{id}/retry`。

## 页面

- 设置 → 系统 → 运行日志：筛选栏、级别统计、列表、详情抽屉（含堆栈）、实时尾随、导出、清空。
- 设置 → 服务与连接 → 问题反馈：仓库、令牌、标签、启用开关、连接测试、最近提交与重试。
- 顶栏虫子图标 → 反馈弹窗：类型、标题、正文、自动附日志（可逐条取舍）、提交结果与 GitHub 链接、手动提交兜底。

## 前端错误采集

- `window.error` 与 `unhandledrejection` 全局监听。
- React `ErrorBoundary` 捕获渲染崩溃并展示可恢复的兜底页。
- axios 拦截器上报 5xx、网络错误和超时；跳过日志上报接口自身与 401，避免循环。
- 节流：同一签名 5 分钟内只报一次，每分钟最多 20 条。

## 测试

- 后端 pytest：日志写入/筛选/详情/导出/清理/脱敏、客户端上报鉴权；反馈配置加密与掩码、成功提交、失败与重试、标签 422 降级。
- 前端：`npm run typecheck`；构建在收尾时执行。

## 已知取舍

- 日志写入是尽力而为：数据库不可用时只保证 stderr，不阻塞请求。
- 轮询而非 SSE：实现简单、反向代理友好，代价是 2 秒延迟。
- 浏览器日志上报依赖登录态；未登录页面的崩溃只留在控制台。
