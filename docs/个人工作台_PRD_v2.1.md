### 0.4 组件库迁移口径与本文合并说明

v2.1 把两份文档合成一份可执行基线：业务与交互仍按第 1～13、16～19 章执行；界面视觉按第 14 章；Element Plus 的变量、选择器、暗色和排查方法集中在附录 A。

迁移只换实现手段，不降低已有的产品要求。凡是本文用 Vuetify 语汇写过的视觉要求，按下面这张表换算成 Element Plus 的等价做法，研发不得因为“Element 里没有同名配置”就删掉对应要求。

| 原 Vuetify 语汇 | Element Plus 下的等价做法 | 是否改变产品要求 |
| --- | --- | --- |
| `variant="tonal"`（轻底色按钮） | 自定义 `.btn-tonal` 类：主色 8%～12% 透明底 + 主色文字；或 `el-button plain` 配合变量调整 | 不改变：仍要求“主要带文字操作用轻底色” |
| `variant="text"`（无底色图标按钮） | `el-button text` 或 `link`，纯图标时配 `circle` 控制命中区 | 不改变 |
| `variant="flat/elevated"` | 默认 `el-button`（无阴影）/ `el-card shadow="always"` | 不改变：仍要求低阴影 |
| MDI 图标（`mdi-*`） | 统一改用 `@element-plus/icons-vue` 线性图标；确无对应语义时可补 `@mdi/js`，但线宽、尺寸必须与其他图标一致 | 不改变：仍要求“线框、单色、轻量、不混套系” |
| 浮动标签（floating label） | `el-form-item` 的 label 常规布局（标签在控件上方或左侧），配合 `label-position`；不引入第三方浮动标签插件 | 不改变：仍要求“标签不被顶栏、父容器、overflow 裁切”，见 14.5 |
| `density="compact"` | `size="small"` + `--el-component-size` 变量 + 组件级 `:deep()` 内边距微调 | 不改变：仍要求紧凑且命中区 ≥ 44px |
| `v-model` 表单校验、`rules` | `el-form` + `el-form-item` 的 `rules`，服务端错误回到对应字段 | 不改变：仍要求前后端双校验 |
| Vuetify 主题对象（`theme.colors`） | Element Plus CSS 变量（`--el-*`）映射到项目自有变量（`--wb-*`），见附录 A.4 | 不改变：仍要求全站一套主题、暗色完整覆盖 |
| `v-data-table` 卡片/表格切换 | 始终用 `el-table`；平板宽表在表格容器内横向滚动 | 不改变：仍禁止平板改卡片布局 |

样式实现的总原则：**优先改变量，其次写组件选择器，`:deep()` 兜住 scoped 内部，最后才考虑 `!important`**。这条原则的完整依据、踩坑记录和速查表在附录 A，前端改动样式前应先读附录 A 再动手。

## 1. 产品定位与目标

### 1.1 用户场景

用户同时经营多个店铺、多个社媒账号。每个店铺或账号都需要执行大量每天、每周、每月重复的工作。用户希望按工作类型集中处理，例如先检查所有店铺的订单，再处理不同社媒账号的发布，而不是反复进入每个对象逐项切换。

此外，用户还需要随时添加临时待办，自行建立业务数据表，编写 Markdown 笔记，用便签记录短内容，并调用翻译 API 或 AI 大模型进行中英互译。

### 1.2 产品目标

- 让重复工作形成明确的“本周期待做清单”，由用户亲自打勾确认完成。
- 区分周期工作与临时待办，避免两种完成、逾期和历史规则混淆。
- 让用户不写代码即可创建基础业务数据表并管理数据。
- 让信息录入、查找、复制和复用足够直接，减少不必要的页面跳转。
- 在桌面和平板上保持高信息密度、清晰层级与可靠操作。
- 只有一个使用者，但必须通过登录隔离所有私人内容和附件。
- 可以在自有服务器上长期运行，重启、更新、备份与恢复不丢数据。

### 1.3 范围总览

| 功能模块 | 最终范围 |
| --- | --- |
| 店铺打卡 | 独立事项、统一工作分组、日／周／月周期、勾选与取消、备注、历史、归档恢复 |
| 社媒打卡 | 独立页面和账号事项，执行规则与店铺一致 |
| 待办 | 多清单、说明、截止日期或时间、一层子任务、父子联动、自动与手动排序 |
| 数据表 | 自定义基础字段、数据 CRUD、临时筛选排序、附件、Excel 导入导出 |
| 笔记 | Markdown、单层文件夹、多标签、图片、自动与手动保存、历史版本 |
| 便签 | 标题、正文、单分类、背景颜色、搜索、编辑、正文复制 |
| 翻译 | 百度、有道、DeepSeek；中文与英语；忠实翻译；查看与复制历史 |
| 回收站 | 数据表、记录、笔记、便签保留 30 天，支持恢复与彻底删除 |
| 基础能力 | 登录、30 天会话、修改密码、主题记忆、受保护文件、服务器部署与备份 |

### 1.4 不在本版范围内

不新增总览仪表盘、多用户或权限角色、公开注册、协作分享、店铺密码托管、自动执行平台工作、平台数据抓取、统一事项模板、指定星期或日期的复杂重复规则、消息推送、离线写入、手机专用版本。

不新增表格公式、关联表、汇总、保存视图、单元格直接编辑、表格卡片视图、Excel 自动去重或匹配更新、Excel 附件迁移、导出附件 ZIP 包、笔记多级文件夹、富文本优先编辑、笔记普通文档附件、便签多标签或历史版本、翻译批量处理、多语言扩展、文案改写、自定义提示词或译文编辑。

便签的“分类”已纳入本版，不应因旧稿曾写“便签不做标签”而删除。分类为一个可选分类值，不等同于多标签系统。

## 2. 用户路径与工作流

### 2.1 日常主流程

登录 → 默认进入“店铺打卡／今日” → 按工作分组处理各店铺事项 → 完成后手动勾选，必要时写备注 → 切换本周／本月 → 切换社媒打卡 → 根据需要处理待办、数据表、笔记、便签或翻译。

### 2.2 六类典型任务

| 场景 | 用户操作 | 应获得的结果 |
| --- | --- | --- |
| 检查所有店铺订单 | 进入店铺今日页，查看“订单处理”分组 | 同组中看到不同店铺的事项，分别打勾 |
| 临时采购任务 | 在“采购”清单中添加待办并设置截止时间 | 留在未完成区，到期后标记逾期，仍可完成 |
| 建立商品台账 | 新建表，配置文字、数字、日期、状态、附件字段 | 在表单中管理数据，可从侧栏直接打开该表 |
| 保存运营方法 | 创建 Markdown 笔记，放入文件夹并加标签 | 编辑自动保存，可查阅和恢复旧版本 |
| 记录供应商信息 | 新建有标题、有分类的便签 | 快速找到并复制正文，复制内容保留换行 |
| 翻译一段文本 | 选服务、选语言、输入并翻译 | 得到只读译文，历史出现在下方，可查看复制 |

### 3.2 导航要求（NAV）

- NAV-01：“打卡”“数据表”为分类行，点击主要行为是展开／收起，不能意外跳转到其他业务页。
- NAV-02：“店铺打卡”“社媒打卡”各有独立页面，当前项选中态明确。
- NAV-03：每张活动数据表直接出现在“数据表”下面，点击表名直接进入其数据页，不先经过列表选择。
- NAV-04：不显示“全部数据表”子菜单，不创建数据表第三级菜单。数据表管理路由可以保留，用于建表、导入和管理，但不重新变成这个已取消的子项。
- NAV-05：同级项目采用一致的层级和缩进规则。表名没有前置图标时，不保留额外 80px 等空白占位，不让表名看起来像第三级。
- NAV-06：长表名可省略显示，但要能通过点击信息入口查看完整表名，平板不能只靠 hover。
- NAV-07：当前基线在表数量超过 10 时提供目录内搜索；导航必须加载所有活动表，不能因 API 每页 100 条就漏掉第 101 张表。
- NAV-08：新建、重命名、删除、导入建表、回收站恢复后，侧栏同步更新；重新获焦或返回页面时可刷新。刷新失败保留旧目录并显示重试。
- NAV-09：直接访问、刷新或浏览器前进后退时，展开当前页面所属分类并标明选中项；其他分类的展开偏好可记住。
- NAV-10：桌面支持展开侧栏和图标栏；图标栏点击分类，可打开临时子菜单。平板使用临时抽屉，选中页面后关闭抽屉，不长期挤占主区。

## 4. 登录、安全隔离与偏好

### 4.1 账号与会话（AUTH）

- AUTH-01：只有一个管理员账号，无公开注册。部署时初始化用户名和独立密码，不携带可直接投入生产的通用固定密码。
- AUTH-02：登录成功后保持 30 天；关闭浏览器后重新打开仍可使用。沿用固定有效期，从登录时计时，不无限续期。
- AUTH-03：会话过期后重新登录。正在编辑时避免无提示丢失输入；无法继续保存时，应保留可复制的输入并说明原因。
- AUTH-04：主动退出吊销当前会话；修改密码验证旧密码，并吊销其他会话。
- AUTH-05：所有业务、文件、附件预览、导出文件、回收站和配置接口都在后端鉴权，不能只依赖前端隐藏页面。
- AUTH-06：密码以安全单向哈希保存；会话使用可吊销的服务端凭证，Cookie 使用 HttpOnly、SameSite 等保护，写操作校验 CSRF。HTTPS 部署启用 Secure Cookie。
- AUTH-07：登录失败采用统一提示并限制连续失败尝试，不能暴露账号存在与否或输出明文凭据。

### 4.2 主题与偏好

支持浅色／深色切换并记住选择，当前默认浅色。主题保存在服务端，桌面和平板读取同一偏好。侧栏展开状态属于界面偏好，可以单独保存在浏览器；密码和翻译密钥不能借此写入浏览器持久化存储。

主题覆盖主页面、弹层、菜单、表格、Markdown、代码块、便签、提示框和错误状态，不允许正文清晰而弹窗仍发白、发灰或不可读。

## 5. 店铺与社媒打卡

### 5.1 核心概念

| 概念 | 产品含义 |
| --- | --- |
| 店铺／社媒账号 | 实际需要处理工作的对象，只保存资料，不接管平台登录 |
| 工作分组 | 订单处理、内容发布等工作类型，统一维护 |
| 打卡事项 | 该店铺或账号长期需要定期完成的工作配置 |
| 本周期事项 | 某条打卡事项在某天、某周或某月产生的一次工作 |
| 完成备注 | 只描述本次工作的情况，例如“今天没有新订单” |
| 历史版本 | 保存当时的事项要求和完成情况，避免后续修改重写过去 |

### 5.2 店铺／账号与分组（CK-01）

1. 每个店铺、每个社媒账号独立配置清单，不共用事项模板，不联动完成状态。
2. 店铺与社媒账号分别管理类型，名称必填；平台、备注可选。平台只是资料，不保存第三方平台密码。
3. 分组统一维护，各店铺或账号的事项从统一分组中选择；每条事项属于一个对象和一个分组。
4. 同一分组聚合展示不同对象的相关工作。例如“订单处理”下依次展示天猫店、小红书店的订单事项。
5. 分组单层，可重命名和排序。分组仍有启用事项或当前未完成工作引用时禁止直接删除，应先调整归属；删除不抹去历史中的当时名称。
6. 对象和事项支持排序。历史和已完成实例的展示信息不能被当前排序或名称修改悄悄覆盖。
7. 配置入口必须可见且可达，能够从对象管理进入“打卡事项”，不能出现只有对象资料、找不到事项配置的情况。

分组中“启用事项”数量按当前有效配置统计，不能把同一事项的多个历史修改版本重复计数。

当前基线：对象名称／平台／分组名称最多 100 字符，对象备注最多 2,000 字符；同类型“使用中”对象不重名。

### 5.3 周期与时间（CK-02）

| 周期 | 北京时间范围 | 本周期要求 | 允许取消的时间 |
| --- | --- | --- | --- |
| 每日 | 当天 00:00 至次日 00:00 | 当天完成一次 | 当天结束前 |
| 每周 | 周一 00:00 至下周一 00:00 | 一周内完成一次 | 本周结束前 |
| 每月 | 每月 1 日 00:00 至下月 1 日 00:00 | 一个月内完成一次 | 本月结束前 |

时间区间左闭右开，以服务器时间判断。时间戳保存 UTC，业务按 Asia/Shanghai 计算；自然月不是固定 30 天，回收站保留 30 天也不是“一个自然月”。

日事项只出现在当天主清单。昨天未完成事项进入历史，不结转今天，也不允许补打卡。周、月事项在各自整个当前周期内有效，不能用“第二天锁定”误套周、月事项。

### 5.4 执行页面（CK-03）

- 店铺、社媒分成两个页面；顶部用“今日／本周／本月”切换，默认打开今日。
- 每个标签内部再按工作分组展示，不按店铺拆成大量独立页面。
- 行内清楚显示所属店铺／账号、标题、完成状态；可查看事项说明和本次备注。
- 用户亲自打勾即表示完成，系统记录服务器完成时间；不要求上传证据、填写业务指标或录入订单数。
- 备注可选，例如“今天没有新订单”；不填备注也能完成。
- 完成后保留原位，显示勾选并适度淡化，方便检查整份清单，不自动移到底部或隐藏。
- 支持店铺／账号筛选，以及全部、未完成、已完成状态筛选。只有主动筛选“未完成”时才隐藏完成项。
- 展示当前查询口径下的完成数量／总数量；无事项时完成率为“—”，不能显示错误的 0/0 百分比。
- 日、周、月的统计独立，历史页面可按对象、周期范围、状态查询。

### 5.5 新增、修改与完成状态（CK-04）

| 操作 | 必须产生的结果 |
| --- | --- |
| 今天新增每日事项 | 立即进入今天清单，今天就需要完成 |
| 周三新增每周事项 | 立即进入本周清单，本周完成一次 |
| 月中新增每月事项 | 立即进入本月清单，本月完成一次 |
| 当前周期勾选 | 记录已完成及服务器完成时间 |
| 当前周期取消 | 恢复未完成并清空完成时间，保留本次备注 |
| 修改标题、说明、分组 | 当前尚未完成且未锁定的事项立即更新 |
| 修改时该实例已经完成 | 本周期这条已完成记录保留完成时的内容 |
| 修改历史对应的长期事项 | 已结束周期中的历史内容不变 |
| 已完成实例随后取消 | 同步最新要求，之后按新要求重新完成 |
| 周期结束 | 已完成和未完成全部锁定，不能补卡、取消或回填时间 |

例：原事项“检查订单”已经完成，随后改为“检查订单并核对退款”。已完成记录暂保留“检查订单”；在当前周期取消后，应显示“检查订单并核对退款”，而不是继续使用旧要求。

沿用细化规则：

- 同一事项同一周期只产生一个实例，重复读取、服务重启、重复提交不能生成重复工作。
- 对相同完成状态重复提交不能重复计数，也不能刷新已成功记录的完成时间。
- 勾选请求在服务器跨过周期边界时到达，应按已结束处理，即使页面还没自动刷新。
- 后续周期采用最新有效要求，备注不带入下一周期。
- 修改重复周期属于特殊变更：保留旧规则当前实例，新周期配置从下一个对应周期生效，保存前展示具体生效时间。不能把它误处理成普通“新增立即进入当前周期”。
- 停用单条事项停止后续生成，当前已产生实例按原有周期规则处理，不等同于归档整个店铺。
- 停机后补齐有效活动区间内遗漏的周期；结束周期以未完成、只读形式呈现，不允许补打卡。

### 5.6 归档与恢复（CK-05）

归档店铺／账号后，从日常清单隐藏并停止后续生成；已有记录保留并锁定。归档不等于删除，不进入通用回收站。

恢复对象后：每日事项从下一个自然日、每周事项从下一个自然周、每月事项从下一个自然月继续。归档期间不补工作，恢复也不解锁过去记录。若当前有同类型同名对象，先改名再恢复，不覆盖其他对象。

系统应记录对象活动区间和锁定原因，不能只根据“现在是否归档”反推过去。

## 6. 待办

### 6.1 清单和普通待办（TODO-01）

用户可创建“工作”“个人”“采购”等多个清单，每条顶层待办属于一个清单。临时待办独立管理，不关联店铺、社媒账号或打卡分组。

| 字段 | 要求 |
| --- | --- |
| 标题 | 必填，最多 200 字符，只填标题也可新增 |
| 说明 | 可选纯文本，当前基线最多 5,000 字符 |
| 截止 | 可不填、只填日期，或指定日期和时间 |
| 完成状态 | 无子任务时由用户勾选，有子任务时由子任务计算 |
| 完成时间 | 系统记录，不由用户回填 |
| 所属清单 | 必有一个；移动父任务时连同子任务一起移动 |

快速新增可通过回车保存；说明／截止时间采用可展开的补充区域，不能长期占用大量首屏高度。表单失败保留输入，不因切换排序丢失新增内容。

### 6.2 一层子任务（TODO-02）

1. 只允许一层子任务，子任务不能再有子任务。
2. 子任务只需要标题和完成勾选；说明和截止日期统一放父任务，不给子任务增加独立的复杂配置。
3. 全部子任务完成，父任务自动完成；取消任意子任务，父任务自动恢复未完成。
4. 有子任务的父任务不能单独手动勾选。禁用状态要说明原因，不能做成“能点但点了没反应”。
5. 父任务进入已完成区后，子任务仍然可查看、可取消；不能只展示父标题导致无法撤销某个子任务。
6. 没有子任务的普通待办不因“子任务数量为零”自动完成。
7. 已完成父任务新增未完成子任务，应恢复未完成；删除部分子任务后重新计算。删除最后一个子任务时保留父任务当时状态，恢复手动完成能力。
8. 父子必须属于同一清单，状态联动与清单移动由服务端在同一事务内处理。

父任务可显示“子任务 x/y”。父复选框即使禁用，也要能清晰识别其已经完成的勾选，不能叠加多重透明度变成近似空白。

### 6.3 截止和逾期（TODO-03）

- 只填日期：当天结束后，也就是次日 00:00，才视为逾期。
- 指定日期和时间：超过指定时刻后逾期，按北京时间展示和判断。
- 逾期仍留在未完成区，标记逾期，随时可以完成，不自动移到历史，不锁定，也不自动改日期。
- 已完成待办不再作为未完成逾期项提醒；取消完成后按实际截止重新判断。

### 6.4 排序、完成区与计数（TODO-04）

默认按截止时间由近到远排序，无截止时间放在后面；用户可切换手动排序。当前基线按清单保存排序模式，手动顺序独立保留，切回自动排序不覆盖手动顺序。

完成的顶层待办移到当前清单底部“已完成”区域；区域可折叠，按完成时间倒序。取消完成后返回未完成区，按当前排序定位。父任务和它的子任务作为一个结构展示，不能被拆散。

左侧清单栏包括标题、可独立滚动的清单列表和底部创建入口；不能出现项目紧贴边界、数量与更多按钮挤在一起、无滚动内容却预留大块滚动条空隙的情况。

当前清单的完成／未完成总数按全部待办节点计数，包含父任务和子任务；未完成区／已完成区标题可以按顶层任务计数，必须与“子任务 x/y”区分。删除预览必须分别展示顶层任务数、子任务数，不能混用不同口径。

### 6.5 删除（TODO-05）

删除清单前明确提示顶层待办和子任务数量，包含已完成内容；确认后连同清单级联删除。删除父任务同样包含其子任务。

待办及清单不进入 30 天回收站，这是与数据表、笔记、便签不同的规则；不可用其他模块的“可恢复”文案误导用户。

## 7. 自定义数据表

### 7.1 表的基本要求（DATA-01）

- 用户可随时创建多张表，自定义表名、可选说明和字段。
- 活动表名不重复，当前最多 100 字符；表说明用于描述用途，不替代字段配置。
- 至少有一个业务字段后再添加数据；系统维护记录 ID、创建时间、更新时间、并发版本和结构版本。
- 系统字段不可被用户删除，用户字段使用稳定 ID；改字段名称不改原数据归属。
- 侧栏直接打开具体表；建表、改名、删除、导入建表和恢复都同步侧栏。

### 7.2 字段类型（DATA-02）

| 字段 | 输入与存储要求 | 基础筛选 |
| --- | --- | --- |
| 短文本 | 文字，当前最多 500 字符 | 包含、等于、为空 |
| 长文本 | 多行文字，当前最多 20,000 字符 | 包含、为空 |
| 数字 | 有限十进制，总精度最多 18 位、小数最多 6 位 | 等于、大于、小于、区间、为空 |
| 日期 | 自然日，不隐式改成带时区时间戳 | 等于、早于、晚于、区间、为空 |
| 单选 | 选择一个属于当前字段的合法选项 | 等于、不等于、为空 |
| 多选 | 一个或多个合法选项，去重保存 | 包含任一、包含全部、为空 |
| 勾选 | 是／否，默认 false | 已勾选、未勾选 |
| 链接 | 完整 http／https 地址，当前最多 2,048 字符 | 包含、为空 |
| 图片／附件 | 一个有效文件引用，单字段最多一个文件 | 有附件、无附件 |

用户原始要求中的“文字”包含短文本、长文本，因此共八类业务字段、九种输入控件。不要因数法不同误删一种。

每个字段可设置名称、类型、适用的必填／默认值、选项和排序。当前每表最多 50 个业务字段，每个选择字段最多 100 个选项；字段名称最多 50 字符，同表内不重复。

数字 0 不是空值，勾选 false 不是缺失；勾选字段不使用容易混淆的“必须为真才算必填”规则。多选必填时至少选择一项。精确数值不以浮点近似结果静默保存。

### 7.3 表结构变更（DATA-03）

| 变更 | 规则 |
| --- | --- |
| 改字段名／排序 | 保留字段 ID 和所有值 |
| 改选项名称 | 保留选项 ID，现有选择仍有效 |
| 删除被引用的选项 | 先调整引用；活动数据和仍可恢复的数据都需要检查 |
| 有数据时新增必填字段 | 提供能补齐活动数据的合法默认值，否则拒绝发布 |
| 可选改必填 | 先检查活动数据，存在空值则提示数量并拒绝 |
| 有非空数据时改类型 | 禁止静默转换；新建字段并迁移数据 |
| 删除字段 | 显示活动数据／回收站受影响数量，确认后执行；字段不进入回收站 |

回收站中删除当时的字段和值保留为历史信息。恢复时按当前结构验证，不擅自重建已经删除的字段，也不能静默丢弃后宣称“完全原样恢复”。

判断字段是否已有非空数据时，包含仍可恢复的回收站数据，不能先软删记录再绕过类型变更保护。

### 7.4 数据增删改查（DATA-04）

- 点击一行打开表单，修改后保存；不做单元格内直接编辑。
- 桌面可使用抽屉；平板表单优先单列，并保证软键盘出现后保存按钮仍能滚动到。
- 新增、编辑由字段配置动态生成控件，前后端都校验类型、必填、选项所属和附件引用。
- 保存携带数据版本和表结构版本；其他设备已修改或结构已变化时，拒绝静默覆盖并保留本地输入。
- 支持单条和批量删除；确认后进入回收站。当前单批删除最多 100 条。
- 查询在服务端进行，不能只筛选当前已经加载的几十行。
- 当前支持最多 10 个 AND 筛选条件、3 个排序字段；长文本、多选、附件不作为排序字段，空值放后，增加稳定次序避免跨页重复或遗漏。
- 常规分页支持 20／50／100，每页默认 50；控件不能把“100 条／页”裁切成难以理解的残缺文字。
- 筛选排序临时生效，不保存命名视图或上次设置；重新进入／刷新按默认规则加载。
- 平板始终保持表格形式，宽表在表格自己的容器中左右滑动，不改成卡片，也不让整个页面横向滚动。

## 8. 图片、附件与文件服务

### 8.1 上传和预览（FILE）

1. 每个附件字段只能放一个文件。需要多个文件时，用户创建多个附件字段。
2. 单文件最大 20 MB，统一按 20,000,000 字节校验，前后端及提示文案一致；网关请求体上限要留出协议开销。
3. 当前允许图片 JPG／JPEG、PNG、GIF、WebP，以及 PDF、TXT、MD、CSV、DOCX、XLSX、PPTX、ZIP 等普通文件；以应用允许列表为准，超范围明确提示。
4. 图片可放大查看，PDF 在线阅读，其余文件下载查看，不在网页里执行上传的程序或活动内容。
5. PDF 阅读包括必要的分页、缩放和适配宽度能力。相关 worker、字体和解码资源随项目本地构建，不因外部 CDN 不可达而变空白。
6. 文件预览和下载必须登录，即使知道文件 URL 也不能绕过鉴权。

### 8.2 生命周期与上传竞态

- 上传先形成暂存文件，记录／笔记保存成功后再建立正式引用。
- 替换附件时，旧文件在保存成功前仍然有效，不能先删旧文件、后因新保存失败导致两边都丢失。
- 上传未完成时，不允许提交一个缺少文件引用的记录；关闭／取消操作也要有一致策略，不能残留后台请求把附件绑定到错误记录。
- 无论上传成功、失败或取消，界面都要解除加载锁定；不能一直停在“保存不可点击”。
- 当前未绑定暂存文件、导入导出临时文件通常保留 24 小时；业务数据不随临时文件到期被删除。
- 活动数据、笔记当前内容、历史版本和可恢复回收站的引用都要纳入清理判断。仍有有效引用时不能物理删除文件。
- 文件存储在持久化卷，数据库保存引用关系，存储路径不是公开匿名下载地址。

## 9. Excel 导入与导出

### 9.1 支持范围（IO-01）

当前支持 `.xlsx`，不承诺旧版 `.xls` 或 CSV 导入。附件允许上传 CSV，不代表数据表已经支持 CSV 数据导入。

一次选择一个工作表，默认首行为表头，单批最多 10,000 条非空数据、50 个业务字段、20 MB 文件。上限可配置并在使用前说明。

### 9.2 导入已有表（IO-02）

选择目标表 → 上传 Excel → 选择工作表 → 建立列与字段映射 → 查看预览、完整校验 → 用户确认 → 全部作为新数据追加。

### 9.3 根据 Excel 创建新表（IO-03）

上传 Excel → 选择工作表 → 根据表头生成字段草稿 → 用户检查表名、字段类型、选项和映射 → 完整校验 → 确认后建立正式表并一次性导入。

自动推断只是草稿，不能跳过用户对字段类型的检查。失败不留下“表已经建好但只导入一半”的正式表。

### 9.4 原子性与数据转换（IO-04）

- 全部追加，不自动判断业务重复，不匹配已有数据并更新。
- 同一个导入任务的确认重试应幂等，不能重复追加；用户另开新批次再导相同文件，按新批次追加，不偷偷去重。
- 任意一处错误，本批次全部不导入；错误报告标明原 Excel 行号、列名及原因，修正后重新提交。
- 预览不等于只检查预览的前几行，必须校验整批数据；确认时结构发生变化也要重新校验或拒绝，不能半批成功。
- 全空行可以跳过，但错误位置保留原工作表行号，不能因跳空行而偏移。
- 空表头、重复表头要求修正；字段映射使用稳定 ID。
- 日期兼容 Excel 日期和标准日期文本；勾选值支持当前约定的 true／false、是／否、1／0；多选可使用明确的分隔符并在映射预览中调整。
- 文本字段保持应有的显示信息。例如文本 SKU“00123”，或数字单元格采用补零格式后映射为文本，应保留相应前导零；原文件已经丢失的信息不凭空猜测恢复。
- 不执行 Excel 公式；没有可用缓存结果时提示错误，不把公式当作服务端代码运行。
- 不提取嵌入图片、不访问本地文件路径、不抓取附件 URL。先导入普通字段，附件以后在表单上传。
- 必填附件不能通过本次导入满足时，应明确阻止并要求调整字段配置，不能绕过必填。
- 普通“链接”字段可按正常数据导入；这与自动下载链接作为附件是两回事。

### 9.5 导出（IO-05）

用户选择“全表”或“当前筛选结果”。筛选结果指全部匹配数据，不仅当前分页，并沿用当前排序。

附件字段导出文件名和下载链接，链接仍需要登录工作台；不额外打包文件，不把图片和文档嵌入 Excel。导出文件本身也需要鉴权下载。

导出排除回收站内容，并采用一致的数据口径，避免导出过程中发生编辑造成同一份文件前后不一致。普通文字按文本写入，不能被 Excel 误作为公式；日期、数字保持对应含义和精度。

### 9.6 导入导出任务状态

任务应具有 ID 和可查询状态，包含预览／待修正／可确认／处理中／成功／失败。成功数量等于实际提交数量；错误可查看或下载。刷新页面后能查询任务结果，前端请求超时不自动等于后台任务失败。

## 10. Markdown 笔记

### 10.1 分类、搜索和编辑（NOTE-01）

- 同时支持文件夹和标签：文件夹单层，每篇最多一个文件夹，可以有多个标签。
- 未指定文件夹为“未分类”；删除文件夹不删除笔记，转到未分类；删除标签只解除标签关系。
- 笔记有标题、Markdown 正文、创建／更新时间、分类和标签。当前标题最多 200 字符，正文最多 1 MiB UTF-8，新建可显示“未命名笔记”。
- 按标题和正文搜索，与文件夹、标签筛选组合，默认按更新时间倒序。
- 直接写 Markdown 源码；桌面并排编辑与预览，平板切换“编辑／预览”。
- 预览支持常用标题、列表、引用、表格、链接和代码块，安全处理 HTML、事件和危险链接，不执行脚本。

### 10.2 图片与保存（NOTE-02）

选择上传或粘贴图片，成功后插入正文引用并在预览显示。图片通过登录保护的文件服务加载，不把大段 Base64 当作正常存储方案。笔记不提供 PDF 或普通文档附件功能。

当前停止输入约 1.5 秒后自动保存，同时保留手动保存按钮，并清楚显示“保存中／已保存／保存失败”。自动保存失败保留正文，可重试或复制；不能显示“已保存”但列表摘要、正文或数据库仍然是旧内容。

离开时存在未保存内容应提醒；会话、网络、版本冲突不能静默清空编辑内容。同一篇在两个设备同时修改时，保留本地输入并提示冲突，不直接覆盖另一份内容，也不擅自自动合并。

### 10.3 历史版本（NOTE-03）

- 保留最近 100 个历史版本，可查看旧内容并恢复。
- 首次保存建立历史版本；持续编辑每 5 分钟形成一个历史版本；有变化的手动保存也保留历史，无变化不重复创建。
- “当前正文自动保存”和“保留一个历史版本”是两种频率，不能误实现为每 5 分钟才保存正文。
- 恢复前先保留当前内容，再把选中的旧标题、正文和图片引用恢复为新的当前内容；不抹去中间历史，恢复时校验并发版本。
- 当前文件夹／标签不因恢复旧正文而自动回滚；删除的分类不自动重建。
- 只要任一历史版本仍引用图片，该图片就不能因为当前正文移除了引用而被清理。
- 删除笔记进入 30 天回收站，正文、分类关联、历史和图片引用按可恢复规则保留。

## 11. 便签

### 11.1 最终内容结构（MEMO-01）

| 字段 | 规则 |
| --- | --- |
| 标题 | 独立于正文，当前可选，最多 200 字符；未填显示“无标题便签” |
| 正文 | 必填纯文本，不能全空，最多 2,000 字符；保留换行 |
| 分类 | 可选，一个便签最多一个分类，最多 80 字符；未填为“未分类” |
| 背景颜色 | 默认、黄色、绿色、蓝色、粉色、紫色六种预设色标识 |
| 时间 | 创建／更新时间，由系统维护 |

“需要标题和内容”表示数据结构和表单都有两个独立位置；当前基线允许标题留空，以保留随手记内容的快捷体验，不能把正文第一行偷偷当成唯一标题字段。

### 11.2 分类与列表（MEMO-02）

- 新建和编辑时可选择已有分类，也可输入新分类名，保存后自动出现在分类选项中。
- 分类是便签的一个值，不新增多级分类树或复杂分类管理模块。
- 列表支持“全部分类／未分类／具体分类”，可与标题或正文搜索组合。
- 改一张便签的分类不批量修改其他便签。当前基线中，没有活动便签使用的分类不再作为可选分类出现。
- 默认按更新时间倒序；新建、编辑或改分类后刷新列表与分类候选，避免旧筛选结果残留。
- 卡片显示标题、正文、分类和更新时间，颜色降低饱和度，在两种主题下都易读。

### 11.3 创建、编辑与复制（MEMO-03）

快速输入聚焦后展开标题、分类、颜色等选项；保存成功清空新增区，失败保留。编辑失败不损坏原卡片。

卡片右下操作区依次提供复制、编辑、删除等明确入口。复制按钮复制**正文内容**，不带标题、分类、时间或额外包装，保留原有换行。成功有反馈；浏览器不允许自动复制时提示打开内容后手动选择复制。

桌面支持 Ctrl／Command + Enter 保存，普通 Enter 换行；平板通过可见按钮完成所有操作。

便签不做历史版本，不默认增加置顶或多标签。删除进入 30 天回收站，恢复保留标题、正文、分类和颜色；旧版本数据没有标题／分类时兼容恢复，不能因升级丢失正文。

## 12. 翻译

### 12.1 范围和翻译行为（TRANS-01）

支持百度翻译、有道翻译、DeepSeek。首版仅中文与英语双向，源语言可自动检测，目标语言明确选择中文或英语。

一次输入一段文本，一次调用一个选定服务，得到一份译文；尽量忠实保留原意、结构和段落，不额外解释、不做文案改写，不同时调用三家比较，也不静默改用其他服务。

AI 服务将原文视为需要翻译的数据，不把原文里夹带的指令当作系统操作，不据此执行服务器命令或调用额外工具。

译文只读，只查看和复制。需要修改的内容由用户复制到其他地方处理，不在此处编辑译文。

### 12.2 页面布局（TRANS-02）

```text
顶部操作条：翻译服务｜源语言｜交换｜目标语言｜翻译｜输入量／上限｜服务设置｜历史入口

中间工作区：
┌──────────────────────────┬──────────────────────────┐
│ 原文                     │ 译文／服务／耗时         │
│ 输入文本                 │ 只读结果                 │
│                          │                          │
│            粘贴／清空原文│        复制译文／清空译文│
└──────────────────────────┴──────────────────────────┘

下方：翻译历史｜搜索原文或译文｜按服务筛选｜刷新
      一条历史：原文摘要＋译文摘要＋语言／服务／时间＋复制操作
      一条历史：……
      分页
```

- 桌面原文、译文并列，宽度和高度协调，底部按钮位置稳定。
- 上方操作条紧凑；服务下拉选中时展示可理解的服务名，不能因拼接过长状态文字而只剩“百度翻译（可…”等残缺内容。
- 顶部操作条内每个 `el-select`／`el-input` 的标签与文字上方留出空间，不被顶栏、父容器 overflow 或边框裁切；操作条改用 flex 时注意不要压到 `el-form-item` 的高度。
- 中间工作区不再占据整屏全部高度，下方历史有实际可用空间。当前实现参考高度为视口约 40%，限制在 260～400px；历史区域至少约 240px，最终根据目标视口检查。
- 较窄平板可切换“原文／译文”，空间足够时并列；工具、历史及操作按钮仍可达，不出现内容压成极窄竖条。
- 不把用户示意图中的多个红框当作空白占位卡片，它们表达的是下方多条历史记录。

### 12.3 四个按钮的含义（TRANS-03）

| 位置 | 操作 | 结果 |
| --- | --- | --- |
| 原文区右下 | 粘贴 | 尝试从剪贴板读取文字填入原文；失败可 Ctrl+V／长按粘贴 |
| 原文区右下 | 清空原文 | 仅清空当前输入及对应输入错误，不删除译文或历史 |
| 译文区右下 | 复制译文 | 复制当前完整译文并反馈 |
| 译文区右下 | 清空译文 | 仅清空当前结果显示，不删除历史记录或原文 |

翻译过程中防止重复提交和中途清空导致结果与输入错配。桌面支持 Ctrl／Command + Enter 发起翻译，不要求平板使用快捷键。

### 12.4 服务设置和凭据（TRANS-04）

| 服务 | 配置内容 |
| --- | --- |
| 百度翻译 | APP ID、应用密钥、启用状态 |
| 有道翻译 | 应用 ID／appKey、应用密钥、启用状态 |
| DeepSeek | API Key、模型名、启用状态；模型采用可配置值 |

三家的凭证结构不同，不能做成同一个“通用密钥”字段。支持保存、替换、清除、启用／停用和连接测试，读取只返回脱敏内容和配置状态。

服务器必须先配置 `WB_ENCRYPTION_KEY`，再允许保存、读取或测试受保护的翻译凭据。缺少主密钥时，明确说明是服务端配置未完成，并提供可定位原因的提示，不能只让保存按钮不可点击、让用户反复改输入。

真实密钥只在服务端加密保存，不写入浏览器持久化存储、普通日志、翻译历史或 Git。主密钥属于部署配置，不能随更新重置；丢失主密钥不能通过“重新生成一个”解开旧凭据。

连接测试是真实外部请求，可能消耗额度，界面需要提前说明。默认使用官方服务地址；若提供自定义地址能力，应限制 HTTPS 并防止访问本机、私网或云元数据地址。

### 12.5 输入限制与异常（TRANS-05）

当前实现基线：百度 6,000 字节、有道 5,000 字符、DeepSeek 4,000 字符。这些是应用目前采用的能力值，**不是对供应商所有账号规格或未来 API 上限的承诺**，实际联调和变更应以账号服务及能力配置为准。

- 空输入或超限不可提交，实时显示数量与正确单位；中文字数不等于 UTF-8 字节数。
- 不静默截断，不自动拆分为多个付费请求，不自动切换服务。
- 当前连接超时 10 秒、整体超时 60 秒；超时、限流、鉴权、余额／额度、未配置、停用和网络失败区分提示。
- 失败保留原文及已有结果，由用户主动重试，不自动重复付费调用。
- 新原文发起的请求不能被较早返回的旧结果覆盖；列表搜索同样不能发生旧请求覆盖新筛选的情况。

### 12.6 历史记录（TRANS-06）

1. 成功时保存原文、译文、源／目标语言、服务、模型、保留原意模式及时间；失败不伪装成成功历史。
2. 历史直接显示在页面下方，当前每页 20 条，支持搜索原文／译文、按服务筛选、刷新和分页。
3. 行内可查看摘要，打开详情查看完整原文和译文，可分别复制。
4. 历史为只读，最终不提供“重新使用／载入输入／再次翻译／编辑译文”入口。
5. 当前用户界面不提供逐条删除或清空历史按钮。代码中既有的维护接口不等于新增用户需求，不得因此重新暴露旧入口。
6. 清空原文或当前译文不影响历史；查看、搜索、复制历史不调用外部翻译服务，不消耗翻译额度。
7. 服务停用、配置替换或模型变化不改写旧原文、译文和当时使用的服务信息；当前沿用不自动过期策略。

## 13. 回收站与不同删除规则

### 13.1 删除行为总表（TRASH-01）

| 内容 | 行为 | 是否属于 30 天回收站 |
| --- | --- | --- |
| 整张数据表、数据记录 | 软删除，可恢复或彻底删除 | 是 |
| 笔记 | 保留正文、历史及文件引用 | 是 |
| 便签 | 保留标题、正文、分类和颜色 | 是 |
| 店铺／社媒账号 | 归档，保留历史 | 否 |
| 打卡事项 | 停用／调整有效区间，保留既有实例 | 否 |
| 待办及清单 | 数量确认后删除，包含子任务 | 否 |
| 数据字段 | 影响确认后调整表结构 | 否 |
| 笔记文件夹／标签 | 移到未分类或解除关联，不删笔记 | 否 |
| 翻译历史 | 当前用户界面只读，无删除入口 | 不承诺 30 天恢复 |

### 13.2 共同规则（TRASH-02）

- 保留期从删除时刻起算 30×24 小时，不按自然月算；到期立即不可恢复，后台清理延迟不延长保留期。
- 按全部／数据表／记录／笔记／便签筛选，显示名称或摘要、删除时间、剩余天数、恢复和彻底删除操作。
- 回收站内容只读，不能编辑、导入或沿用正常入口下载附件；正常列表、搜索、统计和导出排除已删除内容。
- 彻底删除前确认影响；到期清理和手动清理均要求可重试，不产生重复删除错误。
- 空状态说明与筛选区紧凑，不能把说明文字裁切、盖在背景下面或留下误导性的禁用按钮。

### 13.3 恢复冲突（TRASH-03）

| 场景 | 结果 |
| --- | --- |
| 恢复记录时父表尚未恢复 | 先恢复表，不产生孤立数据 |
| 恢复表时表名冲突 | 要求改名，不覆盖或合并现有表 |
| 恢复记录时新增了必填字段 | 补齐合法值后恢复 |
| 恢复记录时字段或选项已删除 | 展示差异，按当前结构校验，不自动重建旧结构 |
| 整表恢复 | 不自动恢复删除整表之前就已经单独删掉的记录 |
| 整表删除 | 不重置表内原先已删除记录的原保留期限 |
| 笔记原文件夹已删 | 恢复到未分类，并说明分类变化 |
| 笔记原标签已删 | 保留仍有效标签，不重建被删除标签 |
| 旧版便签没有标题／分类 | 兼容恢复原正文及颜色，不丢失旧数据 |

只在所有活动、历史和可恢复引用都消失后才清理实体文件。运维备份独立于回收站，业务彻底删除不承诺同步修改已有历史备份。

## 14. 界面、空间利用与视觉规范

### 14.1 总体目标（UI-01）

用户多次强调“最大化空间利用率”，并指出整体界面过大、过粗、过重。最终目标是**轻量、清晰、紧凑、克制**，不是简单缩小所有字号或压缩全部按钮。

- 工作区跟随侧栏外的剩余视口，不全站固定在 1,440px 等最大宽度而浪费宽屏空间。
- 默认页面外边距约 12～16px，工具条优先一行，放不下才有序换行。
- 顶栏已经显示页面名时，正文不再重复放一个大标题；具体对象名、表名等有独立意义的信息可以保留。
- 打卡、待办、数据表、笔记、翻译等工作页优先利用剩余高度，必要区域独立滚动。
- 避免一个区域内容很少却固定占据整屏，尤其翻译输入区必须给下方历史留空间。
- 空状态表达“下一步做什么”，不通过巨大装饰图、重复说明或厚重边框占满首屏。
- 界面精修不改用户自己创建的标题、表名、分类或正文，也不随意修改 API 字段和路由。

### 14.2 排版和层次（UI-02）

| 元素 | 当前设计基线 |
| --- | --- |
| 正文 | 约 14px，正常字重，清楚可读 |
| 表格、辅助文案、控件文字 | 约 12～13px，区分正文和次要信息 |
| 小标题、页面实体标题、弹窗标题 | 约 15～16px，常用字重 600，避免满屏粗黑 |
| 按钮文字 | 约 500 字重，不额外全大写或拉大字距 |
| 边框与阴影 | 细边框、低对比、低阴影，避免整页厚重卡片 |
| 桌面导航行 | 可以紧凑到约 38px |
| 触控按钮、导航、关键列表行 | 可点击区域至少 44×44 CSS px，不随视觉精简而缩小 |
| 控件高度（输入框／按钮／下拉） | `--el-component-size: 34px`，小号 28px，全局统一，避免同页出现两种高度 |
| 圆角 | 控件 `--el-border-radius-base: 6px`；卡片、弹窗、气泡 12px |
| 表格单元格内边距 | 上下 9px（Element 默认 8px），比默认略紧凑但不挤压两行文字 |
| 分页 | 字号 13px，右对齐 |

以上为设计基线，落地一律通过 Element Plus 变量表达，不在组件里散写像素值。变量名与映射见附录 A。

普通正文与背景对比度基线不低于 4.5:1。已完成／禁用状态可适度弱化，但不能看不清勾选和必要信息。不能把所有文字都归为“次要文本”而整体发灰。

### 14.4 按钮、图标与操作组（UI-03）

- 主要带文字操作使用轻底色（tonal）风格：主色低透明度底 + 主色文字，对应 Element 的 `plain` 或项目自定义 `.btn-tonal` 类；纯图标操作使用 `text` 按钮，不加底色。
- 正常、主要、危险操作用明确文字和颜色区分；删除不能只用颜色暗示，`el-button type="danger"` 也要带“删除”字样。
- 图标统一为线性、单色、轻量，来源统一为 `@element-plus/icons-vue`；不混入不同粗细的多套图标，不随意加彩色圆底。图标必须按需 import，不全局注册（全局注册会让漏 import 变成静默空白）。
- 精修后的侧栏图标约 20px，操作图标 18～20px；触控命中区域与图标本身尺寸分开处理。
- 完成和错误使用勾选、警告等可识别形状，不只显示纯色点。

| 间距对象 | 统一基线 |
| --- | --- |
| 同组文字按钮之间 | 8px |
| 同组纯图标按钮之间 | 4px |
| 不同用途的操作组之间 | 12px |
| 操作组换行的行距 | 8px |
| 表单相邻字段 | 通常 12px，至少避免紧贴与重叠 |

外层容器负责间距，按钮本身不叠加到处不同的左右 margin。操作列宽必须包括按钮、组内间距、组间间距与单元格内边距，不能只加 gap 但仍把列压窄。

**Element Plus 必做的一处清零**：Element 自带 `.el-button + .el-button { margin-left: 12px }`。如果操作组用 flex + `gap` 排版，实际间距会变成 `gap + 12px`；而中间夹了 `el-dropdown` 时相邻关系断掉，那一处又只剩 `gap`，整排按钮间距就会忽宽忽窄。约定是间距只由容器 `gap` 控制，必须清零默认 margin：

```css
.toolbar-actions { display: flex; gap: 8px; }
.toolbar-actions :deep(.el-button + .el-button) { margin-left: 0; }
```

窄屏空间不足时优先让表格内部滚动或合理换行，不把“编辑／归档”“重命名／删除”压成紧贴、重叠或逐字竖排。排序箭头属于一组，应保持合理的相对位置。

### 14.5 标签、提示框与弹层（UI-04）

1. 表单标签与控件不被顶栏、父容器、边框或 `overflow: hidden` 裁切；`el-form-item` 的 label、`el-select` 的选中文字是重点回归位置，翻译页的服务选择框是历史高发点。
2. 只有真实、非空的说明才显示 `el-tooltip`，不能出现鼠标经过后弹出无内容长条。
3. tooltip 即使有内容，也不能因前景与背景近似而看起来空白；浅深主题分别检查。
4. 有子任务的父任务禁用勾选时，提示说明原因，内容可读；平板可通过点击说明入口或常显信息理解，不能只依赖悬停。
5. `el-dialog`、`el-drawer`、`el-select` 下拉、`el-popover`、`el-message`、`el-message-box` 等会被挂到 `body` 的浮层，必须继承同一套主题变量、字体与间距；只在页面内改样式、不管挂载到 body 的浮层，会出现“正文变了弹窗还是旧的”。
6. 长错误信息可换行，提示条不超出视口；有定位价值的错误不能被直接裁掉。
7. 所有保存按钮的禁用原因应可理解，例如必填未填、上传中、保存中、服务器配置未就绪；状态解除后恢复操作。

### 14.6 滚动与布局稳定（UI-05）

- 滚动条轻量、细线、随主题变化，避免粗重轨道和无意义的箭头占位。
- 无滚动内容时不为滚动条永久预留空白槽，防止清单旁出现突兀白缝。
- 待办清单栏、表格、笔记编辑器等按职责滚动，不能全页和子区域同时出现多层无意义滚动条。
- 横竖屏切换、侧栏展开／收起、长表名、长内容和软键盘出现均不能盖住保存、关闭或分页操作。
- 以实际可见边界测量重叠、间距和溢出；不能仅凭样式文件里写了 gap 就判定修复成功。

### 14.7 Element Plus 样式落地约束

Element Plus 的样式是「基础变量 → 组件样式 → 暗色主题」三层，组件内部全部用 `var(--el-*)` 取值。因此本项目的视觉调整必须遵守下面几条，否则会出现“改了样式毫无反应、不报错、不警告”的情况：

1. **引入顺序固定**：`element-plus/dist/index.css` → `element-plus/theme-chalk/dark/css-vars.css` → 项目 `theme.css`（最后）。三者都用 `:root` 选择器、权重相同，后加载的赢。顺序写反的症状是按钮永远是 Element 默认蓝。
2. **两层变量**：先定义项目自有变量 `--wb-*`，再在 `:root` 里把 `--el-*` 指向 `--wb-*`。暗色只覆盖 `--wb-*`，`--el-*` 自动跟随，不给组件逐个写暗色样式。
3. **颜色不散写**：组件里一律 `var(--wb-*)`，禁止硬编码 `#fff`、`#f5f7fa`；否则暗色下会出现“白卡片 + 黑输入框”的割裂（登录页是历史踩坑点）。
4. **scoped 内部用 `:deep()`**：Vue scoped 的 `[data-v-xxx]` 加不到 Element 自己渲染的内部节点上；改表格行高、表头底色、日期选择器宽度这类需求，必须“包一层父容器 + `:deep(.el-xxx)`”，直接给组件根节点加 class 往往打不过 Element 自带的优先级。
5. **先找变量，再写选择器**：弹窗、气泡、输入框都有圆角变量（`--el-dialog-border-radius`、`--el-popover-border-radius`、`--el-input-border-radius`），优先用变量；`--el-button-border-radius`、`--el-select-dropdown-border-radius` 这类名字**不存在**，写了无效，别浪费时间。
6. **`!important` 是红灯**：出现即说明选择器或变量层级写错了，回头改结构，不要在样式文件里层层加码。
7. **不改 `node_modules`**：所有覆盖写进项目 `theme.css`，保证换机器、重装依赖后仍可复现。
8. **表格、弹窗、分页统一配方**：表头底色、行 hover、边框色、遮罩浓度、分页字号都用变量统一定义，不在各页面重复写。

具体变量清单、组件配方、`theme.css` 组织方式、暗色写法和排查顺序见 **附录 A：Element Plus 样式定制与主题实现**。前端在改任何样式前先读附录 A。

## 16. 终端适配与通用交互

### 16.1 验收终端

| 类型 | 必测视口 |
| --- | --- |
| 平板竖屏 | 768×1024 |
| 平板横屏 | 1024×768 |

| 常规桌面 | 1440×900，并检查更宽屏空间利用 |

检查中间宽度，而不是只测试两个端点。桌面 Chrome／Edge、平板 Safari／Chrome 为兼容基线；真实设备结果与浏览器模拟布局结果分别记录，不能互相冒充。

当前宽度约 1280px 起为桌面固定导航，较窄时用可收起抽屉。触控目标尺寸按输入方式保证，不能因为平板有较高分辨率就采用很小的鼠标目标。

当前侧栏参考宽度：桌面图标栏 64px、展开栏 192px、平板临时抽屉 232px。桌面记住收起偏好，平板抽屉关闭后不占正文宽度。

手机不是专项交付目标，但窄屏仍应尽量能完成基本操作，不通过固定最小整页宽度导致完全无法使用。

### 16.2 通用状态

所有列表具备加载中、无数据、无匹配结果、失败和重试状态；表单具备未修改、可保存、保存中、成功、校验失败、网络失败和冲突状态。

慢请求期间避免重复提交；失败保留用户输入。页面切换、切换表和弹层关闭不得把旧请求结果写入新的实体。更新成功后的统计、摘要、分类、目录和列表应及时同步。

保存、复制、上传、删除、恢复等有清楚结果反馈；重要状态不能只通过瞬间消失的颜色变化表达。

### 16.3 剪贴板与协议

普通 Ctrl+V／长按粘贴与浏览器自动读取剪贴板是不同能力。IP＋HTTP 环境可能无法使用自动读取或写入接口，失败应提供手动操作路径，不产生空白错误框。

完整自动剪贴板能力需结合 HTTPS 和目标浏览器权限验收。不能把用户暂用 IP 地址部署理解成已经完成 HTTPS 验收，也不能声称非标准端口本身等于加密或身份保护。

接口统一使用 `/api/v1` 前缀。下表列出当前能力和关键路径，具体字段及方法以项目 OpenAPI 和本版业务规则共同核对，不重新发明第二套并行 API。

所有界面都要恢复保存／上传加载状态；错误不应导致永久禁用。带幂等标识的请求仍要重新校验会话与权限，不能把历史缓存响应变成绕过鉴权的第二条通道。

### 19.2 Docker 与持久化（OPS-02）

- 使用 Docker Compose；数据库、API、Web 有明确启动关系和健康检查，Web 等 API 健康后启动。
- API 容器启动执行数据库迁移；重启和迁移不能重置用户和业务数据。
- 数据库卷、文件卷独立持久化，普通容器重建和更新不删除卷。
- 容器设置合理内存与 CPU 上限及重启策略。当前参考上限：数据库 384 MB、API 640 MB、Web 128 MB。
- Nginx 代理要能重新解析 API 服务地址，避免后端容器重建后仍访问旧地址。
- 小型服务器顺序构建前后端，避免同时构建挤爆内存；必要时可对单次构建指定 HTTPS 包源，不随意修改全局系统配置。
- PDF.js 等构建资源随应用提供；生产健康检查不额外依赖无必要的外部服务。
- 前端组件库为 Element Plus，样式统一走 `index.css` + 暗色变量 + 项目 `theme.css`；图标与按需使用的组件按需引入，不做全量图标全局注册，构建产物体积纳入构建检查（小服务器构建容易因内存和体积双重压力失败）。

### 19.3 完整源码的含义（OPS-03）

必须包含前后端源码、依赖说明和前端锁文件、数据库迁移、Dockerfile、Compose、Nginx 配置、测试、部署 README 和维护脚本，使另一台机器可以重新构建项目。

“全部文件上传”不包括真实 `.env`、账号密码、翻译凭据、数据库、上传附件、私有备份、日志、测试截图、依赖目录和构建缓存。自动生成的前端静态资源可以重新构建，不需要用提交 node_modules 的方式追求“完整”。

清理测试环境前先备份。只移除确认的测试内容与测试附件，不因清理而重置管理员或误删已经配置的翻译服务。测试脚本不得写死生产密码；测试数据库名不能任意指向生产库，开发重置工具应拒绝生产环境。

### 19.4 备份、恢复与更新（OPS-04）

备份需要数据库、上传文件和安全保管的部署配置，尤其翻译加密主密钥。数据库备份和文件备份选择一致的维护窗口，避免数据库指向尚未备份的文件。

恢复前有明确确认，先保护当前数据；优先在独立数据库验证备份可恢复。脚本应支持正常的相对路径、绝对路径和含空格路径，不为简单打包临时再拉一个不必要的工具镜像。

更新步骤：备份 → 同步已确认源码 → 构建 → 应用迁移 → 启动与健康检查 → 登录及关键业务验证。回退涉及数据库结构时，需要配套数据库、附件和配置备份，不能只切换旧镜像就宣布回退完成。

当前服务器采用完整源码归档部署，不保存 GitHub 登录授权。后续应明确源码同步方式，不能对没有 `.git` 的部署目录直接照搬 `git pull`。

生产不保留仿真业务数据。维护备份包含私人内容，独立保存，不提交到源码仓库。

### 21.6 发布阻断与修复闭环

以下情况不能以“基本能打开”通过验收：数据丢失、权限绕过、历史被改写、周期锁定错误、批次部分导入、上传竞态丢附件、父子待办不同步、保存永久锁定、关键操作不可达、按钮重叠、文字明显裁切、提示框不可读、工作台因更新仍代理旧后端地址。

流程：构造可识别的模拟数据 → 按真实工作路径操作 → 截图同时检查 UI → 记录复现与预期 → 修复 → 重测原问题及受影响范围 → 记录版本和证据 → 根据用户要求保留或清理测试内容。不能只修一次 CSS 数值而不在同样视口重新测量。

实体平板、真实翻译服务、公网入口和备份恢复分别留证据；模拟视口通过不等于实体设备通过，内部健康通过不等于公网已经开放。生产测试只建立明确的一次性数据并清理自身数据，不扫描删除已有业务内容。

# 附录 A：Element Plus 样式定制与主题实现

> 本附录由《Element Plus 样式定制指南》合入，并按个人工作台的设计基线（青绿主色、紧凑排版、浅深双主题）改写。变量名与选择器均在 **Element Plus 2.14** 上实测有效。原指南里的 `--crm-*` 前缀统一换成本项目的 `--wb-*`，主色换成第 14.3 节的青绿色。

## A.1 三十秒决策

| 你的需求 | 该怎么做 |
| --- | --- |
| 换主色、圆角、字体、边框颜色 | **改 CSS 变量**（`--wb-*` 再映射到 `--el-*`），一次生效全局 |
| 某个组件的形态（弹窗圆角、表格行高） | **组件选择器覆盖**，或找它对应的变量 |
| 在 `scoped` 样式里改组件内部 | 加父级容器 + `:deep(.el-xxx)` |
| 想用 `!important` 硬压 | **先停下**，99% 说明选择器写错了 |

一句话：**优先变量，其次选择器，最后才考虑 `!important`。**

## A.2 三层结构：先搞懂它怎么取值

Element Plus 的样式是「变量 → 组件 → 主题」三层：

```
① 基础变量      :root { --el-color-primary: #409eff; ... }
② 组件样式      .el-button { background: var(--el-color-primary) }
③ 暗色主题      html.dark { --el-color-primary: （更亮的版本） }
```

**关键点**：组件内部全部用 `var(--el-*)` 取值。所以在 `:root` 改掉变量，所有引用它的组件都会跟着变——这是最省力的改法，也是唯一能保证全局一致的做法。反过来，逐个组件写样式一定会漏，新增组件必错。

## A.3 引入顺序：最容易翻车的地方

```ts
// main.ts
import 'element-plus/dist/index.css'                    // ① 组件库基线
import 'element-plus/theme-chalk/dark/css-vars.css'     // ② 暗色变量
import './assets/main.css'
import './assets/styles/theme.css'                      // ③ 自己的覆盖 ← 必须最后
```

**为什么顺序重要**：`:root { --el-color-primary: ... }` 在三个文件里的选择器权重完全相同（都是 `:root`），而 CSS 的规则是「权重相同时，后加载的赢」。

顺序写反的后果是**改了变量毫无反应**，而且不报错、不警告。历史真实踩坑：

```
现象：按钮永远是 Element 默认蓝 #409EFF，改 theme.css 完全无效
原因：theme.css 引在 index.css 之前，被后者的 :root 覆盖
判断：DevTools 里看 --el-color-primary 的计算值是 #409eff 而不是你设的值
```

这条属于发布前必须核对的项（见 21.5 A82）。

## A.4 第一层：变量映射（覆盖 90% 的需求）

### A.4.1 浅色主题：把 `--el-*` 指向 `--wb-*`

```css

  --wb-bg: #f5f7fa;
  --wb-surface: #ffffff;
  --wb-surface-subtle: #edf2f6;
  --wb-text: #334155;
  --wb-text-secondary: #475569;
  --wb-text-tertiary: #94a3b8;

  /* 主色：light-3/5/7/8/9 与 dark-2 是一整套，必须同批给出，
     只改 --el-color-primary 的话，hover、禁用、浅底按钮仍是默认蓝 */

  --el-color-primary-light-5: #9cbbb7;

  --el-color-success: #16a34a;

  --el-text-color-secondary: var(--wb-text-tertiary);
  --el-text-color-placeholder: var(--wb-text-tertiary);

  /* 边框 / 填充 / 背景 */
```

### A.4.2 一个技巧：让 Element 变量指向你自己的变量

```css
:root {
  --wb-primary: #39776f;                     /* 先定义自己的 */
  --el-color-primary: var(--wb-primary);     /* 再让 Element 引用它 */
}
html.dark {
  --wb-primary: #8ccabe;                     /* 只改一处，Element 自动跟随 */
}
```

这样暗色模式只需要覆盖 `--wb-*`，不用给每个组件写一遍暗色样式。

### A.4.3 怎么查某个组件用了哪些变量

```js
// ① 控制台直接问（最快）
getComputedStyle(document.documentElement).getPropertyValue('--el-color-primary')

// ② 选中元素 → DevTools 的 Computed 面板 → 过滤框输入 --el-
// ③ 全局搜源码
```

```bash
# 在 node_modules/element-plus/dist/index.css 里搜某个变量被谁引用
grep -o -- '--el-table-header-bg-color' node_modules/element-plus/dist/index.css | wc -l
```

> 注意 `grep` 遇到以 `--` 开头的字符串会被当成命令行参数，必须加 `-e` 或 `--`。

## A.5 第二层：组件选择器覆盖

有些东西没有对应变量，或者变量管不全，就得直接写组件选择器。本项目需要四处：

```css
.el-card {
  --el-card-border-color: var(--wb-border);
  border-radius: 12px;
}
.el-dialog {
  --el-dialog-border-radius: 12px;   /* 这个变量真实存在，优先于 border-radius */
  box-shadow: 0 8px 24px rgba(16, 24, 40, 0.1);
}
.el-message-box {
  border-radius: 12px;
}
.el-popover.el-popper {
  --el-popover-border-radius: 12px;
  box-shadow: 0 8px 24px rgba(16, 24, 40, 0.1);
}
```

**先找变量，再写选择器**。弹窗、气泡、输入框都提供了圆角变量（`--el-dialog-border-radius`、`--el-popover-border-radius`、`--el-input-border-radius`），用变量比写 `border-radius` 更稳——组件内部可能还有 `overflow: hidden` 之类依赖。

⚠️ 这几个名字**不存在**（实测无定义），别写：`--el-button-border-radius`、`--el-message-border-radius`、`--el-select-dropdown-border-radius`、`--el-select-input-height`。

## A.6 第三层：`scoped` 里改组件内部

Vue 的 `scoped` 会给选择器加 `[data-v-xxx]` 属性，而 Element 组件的内部 DOM 是它自己渲染的，**没有你的属性**，所以写不进去。必须用 `:deep()`。

### A.6.1 表格行高、表头底色

```vue
<el-table class="record-table" ... />
```

```css
<style scoped>
.record-table :deep(.el-table__cell) {
  padding: 9px 0;                      /* 默认 8px，行更紧凑（对应 14.2 节） */
}
.record-table :deep(th.el-table__cell) {
  background: var(--wb-surface-subtle);
  color: var(--wb-text-secondary);
  font-size: 12px;
  font-weight: 500;
}
</style>
```

### A.6.2 日期选择器宽度（踩过的坑）

**错误写法**：

```vue
<el-date-picker class="filter-date" />
```
```css
.filter-date.el-date-editor { width: 240px; }   /* 无效 */
```

原因：`scoped` 编译后变成 `.filter-date.el-date-editor[data-v-xxx]`，虽然能匹配，但**优先级打不过 Element 自己的样式**，加上内部还有 `.el-date-editor--daterange { width: 350px }` 这类规则，很容易失效。

**正确写法**：外面包一层，用 `:deep()` 从父级往下选。

```vue
<div class="date-wrap">
  <el-date-picker type="daterange" ... />
</div>
```
```css
.date-wrap :deep(.el-date-editor) {
  width: 240px;
}
```

### A.6.3 相邻按钮的间距（本项目必须清零）

Element 有这条默认样式：

```css
.el-button + .el-button { margin-left: 12px; }
```

如果外层用 flex + `gap: 8px` 排版，实际间距会变成 **20px**；而中间若夹了一个 `el-dropdown`（不算 button 的相邻兄弟），那一处又只有 8px——于是整排按钮**间距忽宽忽窄**。修法：清零它，间距只由 `gap` 控制。

```css
.toolbar-actions {
  display: flex;
  gap: 8px;
}
.toolbar-actions :deep(.el-button + .el-button) {
  margin-left: 0;
}
```

这与 14.4 节“外层容器负责间距”是同一条规则的具体落法。

## A.7 暗色模式：别给组件写暗色

❌ 错误做法：`html.dark .el-button { background: #333 }`（要写几十个组件，新增组件必漏）

✅ 正确做法：只覆盖 `--wb-*`，让 Element 的变量引用你的变量（见 A.4.2）。

```ts
// main.ts 必须引入官方暗色变量文件
import 'element-plus/theme-chalk/dark/css-vars.css'
```

```css
/* theme.css */
html.dark {
  color-scheme: dark;              /* 原生滚动条、输入光标跟着变 */
  --wb-bg: #181e27;
  --wb-surface: #222b37;
  --wb-surface-subtle: #2b3645;
  --wb-text: #e1e8f0;
  --wb-text-secondary: #c2cede;
  --wb-text-tertiary: #8a97a8;
  --wb-border: #2f3945;
  --wb-primary: #8ccabe;

  --el-color-primary: var(--wb-primary);
  /* 深色下的浅底不要再与白色混合（会发灰、破坏层次），
     改用半透明主色，暗色下更干净 */
  --el-color-primary-light-3: rgba(140, 202, 190, 0.55);
  --el-color-primary-light-5: rgba(140, 202, 190, 0.40);
  --el-color-primary-light-7: rgba(140, 202, 190, 0.26);
  --el-color-primary-light-8: rgba(140, 202, 190, 0.18);
  --el-color-primary-light-9: rgba(140, 202, 190, 0.12);
  --el-color-primary-dark-2: #a9d8ce;   /* 深色下“更暗”没有意义，改用更亮的强调 */
  /* 其余 --el-* 已在 :root 里指向 --wb-*，这里不重复写 */
}
```

**容易漏的地方**：硬编码在自己组件里的颜色不会跟随主题。登录页曾栽过——页面背景写死 `#f5f7fa`、卡片写死 `#fff`，而 Element 输入框跟着主题变深，暗色下就成了「白卡片 + 黑输入框」的割裂外观。**所有颜色都走变量**，这条要在 code review 时卡住。

## A.8 图标风格统一

`@element-plus/icons-vue` 同时提供**实心**和**线性**两套风格，混用会显得廉价。本项目统一线性（对应 14.4 节“线框、单色、轻量”）：

| 实心（不要用） | 线性（推荐替代） |
| --- | --- |
| `TrendCharts`（填充柱状） | `DataLine` |
| `List`（三条粗块） | `Tickets` |
| `PieChart` / `Histogram` / `DataAnalysis` | `DataLine` / `Odometer` / `Monitor` |

判断方法：打开图标库预览页，看笔画是否有粗细变化、是否填色块。

另外**按需 import，别全局注册**：

```vue
<script setup lang="ts">
import { Filter, Plus } from '@element-plus/icons-vue'
</script>
<template>
  <el-button :icon="Plus">添加</el-button>
</template>
```

全局注册（`app.component('Filter', Filter)`）会让「忘了 import」变成静默失败（图标空白、只有控制台一条警告），按需 import 则直接编译报错。

### A.9.5 软色标签（便签颜色、状态标识）

```css
  font-size: 12px; display: inline-flex; align-items: center;
}
.memo-chip.c-yellow { background: #fdf6e3; color: #8a6d1f; }
.memo-chip.c-green  { background: #ecfdf3; color: #15803d; }
/* ……每色一对「浅底 + 深字」，暗色下换成半透明底 + 亮字 */
```

便签六色同样走 `--wb-memo-*` 变量，暗色下统一替换，不在组件里写死色值（第 11.2 节要求“降低饱和度，两种主题下都易读”）。

## A.10 本项目 `theme.css` 的组织

分五段，顺序本身就是文档：

```css
:root { /* ① 自己的设计变量 --wb-* */ }
:root { /* ② 把 --el-* 映射到 --wb-* */ }
body { /* ③ 全局基础（字体、背景） */ }
.el-card, .el-dialog, .el-message-box, .el-popover { /* ④ 少量组件级补丁 */ }
html.dark { /* ⑤ 只覆盖 --wb-*，其余自动跟随 */ }
```

原则：**④ 越短越好**。如果这里开始出现 `!important`，说明你该回去改 ①②。

## A.11 变量没生效？按这个顺序查

1. **看计算值**：DevTools → 选中元素 → Computed → 搜 `--el-xxx`，是不是你设的值？
2. **如果是默认值** → 引入顺序问题（A.3），或变量名拼错。
3. **如果是对的值但样式没变** → 组件没引用这个变量（换别的变量，或写选择器）。
4. **如果是 `scoped` 里没生效** → 缺 `:deep()`，或缺父级容器（A.6.2）。
5. **都排除还不行** → 有没有行内样式 / 组件 props（`header-cell-style`、`style`）在覆盖？行内样式优先级最高。

## A.12 反模式清单

| 别做 | 为什么 | 该怎么做 |
| --- | --- | --- |
| 直接改 `node_modules/element-plus` | 重装就没了，且团队无法复现 | 写在自己的 theme.css |
| 到处 `!important` | 后面所有覆盖都得加，越滚越脏 | 提高选择器特异性或改用变量 |
| 暗色下逐个组件写 `#333` | 新增组件必漏，维护地狱 | 覆盖变量（A.7） |
| 把颜色写成 `#fff` 散落各处 | 换主题/改配色要全项目搜 | 一律 `var(--wb-*)` |
| 用 `el-tag` 硬凑语义色 | 颜色空间不够用 | 自定义 span + 变量（A.9.5） |
| 全局注册所有图标 | 忘 import 时只有警告，图标静默消失 | 按需 import（A.8） |
