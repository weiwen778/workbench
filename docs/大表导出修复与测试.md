# 大表导出修复与实测（2026-11-03）

- 原导出每写入一个单元格都调用 `ws.max_row`，反复扫描已写单元格，宽表、大表耗时快速增长。
- 改用 openpyxl write-only 工作表；数据库每批读取 500 条，直接写磁盘，避免全量记录和工作簿常驻内存。
- 普通导出和按原始字段筛选的导出按批投影公式，移除它们原有的 10000 行公式导出限制。按计算列筛选/排序仍沿用共享计算引擎的 10000 行保护；关联表解析也仍有其原有限制。Excel 单页最多导出 1048575 条数据加一行表头。
- 保留文本公式防护、附件超链接、选项名称、计算错误提示和删除记录排除。
- 浏览器改为直接下载链接，避免异步 `window.open` 被拦截；导出请求超时放宽至 180 秒，并显示生成提示。
- 普通表格字段数、导入列数上限统一从 50 提高至 200；导入草稿和确认阶段也检查总列数，防止通过追加列绕过限制。字段名称长度保持 50 字。

## 可重复测试

在仓库根目录执行：

```bash
cd server
.venv/bin/python -m pytest -q -s tests/test_large_exports.py
```

脚本批量生成数据，使用隔离 SQLite 测试库，不接触业务数据。也可通过 `WB_TEST_DATABASE_URL` 指向独立的本地 PostgreSQL 测试库；数据库名称必须以 `workbench_element_test` 开头。测试框架会重建该测试库中的表。

## 本机结果

| 场景 | SQLite | PostgreSQL 14 |
| --- | --- | --- |
| 10000 行 × 200 列，全部导出 | 17.959 秒 | 17.372 秒 |
| 上述宽表筛选 100 行并降序导出 | 0.275 秒 | 0.450 秒 |
| 10001 行、含公式列，全部导出 | 0.600 秒 | 0.654 秒 |

耗时包括导出请求及下载文件，受机器负载影响。宽表生成文件约 6.84 MB；测试重新打开 XLSX 核对全部 200 万个单元格及筛选后的顺序，并验证公式结果、公式样式文本保持为文本、删除记录排除、200/201 列边界。

另外在独立 PostgreSQL 测试库启动临时 HTTP 服务，用 Playwright 真实登录、打开 10000 行 × 5 列表格、点击导出并接收浏览器下载；逐行核对下载文件，确认没有新窗口和浏览器运行错误。业务库未写入测试数据。
