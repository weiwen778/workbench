# 服务器运行监控

设置 → 系统与备份 → 运行状态显示 CPU、内存、Swap、系统负载、磁盘容量、磁盘读写、网络收发速率、系统运行时长和工作台进程内存。每 5 秒采样，保留本次采集器启动后最近 15 分钟趋势；关闭页面或切换标签时暂停界面轮询。超过 20 秒没有新样本会明确提示采集中断。

本地 WSL 监控的是 WSL Linux 环境。原生 Linux 服务直接读取所在服务器。Docker Compose 自带 `host-metrics` 采集器，使用宿主机 PID 与网络命名空间，以及只读根目录挂载采集整机指标；丢弃全部 Linux capabilities，禁止提权，限制 64 MB 内存和 0.1 核 CPU。采集器没有 HTTP 服务、不开放端口、不挂载 Docker socket，也不读取数据库或工作台密钥。只向共享卷原子写入指标 JSON，API 以只读方式挂载该卷。

部署执行 `docker compose up -d --build` 会同时启动采集器。API 的 `WB_HOST_METRICS_FILE=/metrics/current.json` 指向共享文件。采集器不可用时回退到容器指标，并明确显示“容器运行环境”，不会把容器内存配额误标成服务器整机内存。容器磁盘显示挂载文件系统共享容量；采集器首次 CPU、网络速率显示 —，下一次采样后显示数值。

`GET /api/v1/system/metrics` 要求登录，响应禁止缓存；公共健康检查保持最小信息。指标不写业务数据库，重启采集器会清空趋势。负载警示只表示当前样本，不是持久告警服务。
