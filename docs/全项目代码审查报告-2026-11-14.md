## 结论摘要

发现多项需要处理的问题：开发模式下的 React StrictMode 可能令部分页面加载卡住；子任务跨清单移动会破坏父子任务归属一致性；翻译自定义上游的 DNS 校验与连接解析存在间隔；登录失败记录没有保留期；翻译历史分页为计算总数会加载全部匹配记录。

前端类型检查通过。后端全量测试有 1 项失败，原因是测试依赖真实 DNS 的解析结果；当前 WSL 将测试域名解析到非公网地址，应用的拒绝行为符合安全校验逻辑，但不符合该测试对 NXDOMAIN 的假设。

`main...HEAD` 为空，因此本报告评审的是当前仓库快照，而非某个分支的变更集。未发现专门的代码规范文件；以 README 中的架构约定和功能文档作为项目指导。部分旧文档仍以 Vue/Element Plus 为技术基线，当前主线已是 React + MUI。

## 确认问题

优先级是审查建议，不是项目现有的正式 SLA。

### 1. [P2] StrictMode 开发模式下打卡、待办和表格加载可能卡住

- **位置：** `web-react/src/main.tsx:12-16`；`web-react/src/pages/Checkin.tsx:55-57`；`web-react/src/pages/Todos.tsx:47-49`；`web-react/src/components/TableView.tsx:111-113`
- **原因：** React StrictMode 在开发模式重放 effect 的 setup/cleanup。cleanup 将 `viewActive.current` 设为 `false`，后续 setup 没有重新设为 `true`。请求响应因此被忽略；打卡的 loading 状态也可能一直无法结束。
- **建议：** 在 effect setup 中恢复活动标记，或使用 effect/request 作用域的取消标记；增加开发模式下的首屏加载回归测试。
- **验证边界：** 已从代码路径确认风险，未启动浏览器针对该场景复现。

### 2. [P2] 单独移动子任务会破坏父子任务清单归属

- **位置：** `server/app/routers/todos.py:378-389`
- **原因：** move 接口修改所选任务的 `list_id`；只有当所选任务是父任务时，才会同步子任务。单独移动子任务会让它与父任务的 `list_id` 不一致。列表仍按父任务展示子任务，但统计按子任务自己的清单归类。
- **建议：** 禁止单独移动子任务，或让移动接口原子地移动整个父子任务组；补充移动后列表展示、计数和清单删除/恢复测试。

### 3. [P2，条件性安全风险] 翻译上游 DNS 校验与实际连接未绑定

- **位置：** `server/app/services/providers.py:73-105`
- **原因：** 保存配置和请求前会检查 DNS 结果是否为公网地址；随后 `httpx` 会自行解析并连接。两次解析之间 DNS 结果变化时，私网地址限制可能失效。信息聚合的 `server/app/services/public_http.py` 已采用连接经校验 IP 的设计。
- **建议：** 翻译请求复用能连接已校验 IP、同时保留 Host/TLS 校验的传输层，并覆盖解析结果变化的测试。风险针对配置了自定义翻译上游的部署。

### 4. [P2，长期运行风险] 登录失败记录没有保留期或全局总量限制

- **位置：** `server/app/routers/auth.py:49-80`；`server/app/models.py:67-74`；`server/app/maintenance.py`
- **原因：** 每次失败登录都会写入 `login_attempts`；限流按用户名及用户名/IP 组合计数，代码中未发现过期记录清理或全局 IP 限制。长期暴露的服务可能持续累积记录。
- **建议：** 增加记录保留期清理，并按来源 IP 或全局设置请求速率/记录上限。

### 5. [P2，数据规模增长时的性能问题] 翻译历史分页会加载所有匹配记录

- **位置：** `server/app/routers/translate.py:316-324`
- **原因：** `len(db.scalars(stmt).all())` 为计算总数加载全部匹配实体，包括原文和译文；随后又单独加载当前页。
- **建议：** 用数据库 `COUNT` 查询总量，分页查询只读取当前页。关键词搜索的匹配条件应在两条查询中保持一致。

### 6. [P2，测试可靠性] DNS 错误测试依赖真实解析器

- **位置：** `server/tests/test_translate.py:367-379`
- **表现：** 后端全量测试中 `test_base_url_rejects_private_https_and_dns_failure` 失败，预期 `UPSTREAM_DNS_FAILED`，实际得到 `UPSTREAM_URL_REJECTED`。
- **原因：** 当前 WSL 将 `does-not-exist.invalid` 解析到 `198.18.0.82`；该地址不是公网地址，应用正确地走了“拒绝非公网地址”分支。
- **建议：** 在测试中 mock `socket.getaddrinfo` 抛出 `socket.gaierror`，不要依赖外部 DNS 的行为。
