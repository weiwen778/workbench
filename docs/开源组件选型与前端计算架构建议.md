# 开源组件选型与前端计算架构建议

**编写日期：** 2026-11-14  
**项目：** 个人工作台 / Workbench  
**当前主线：** React 18 + TypeScript + MUI；FastAPI + SQLAlchemy + PostgreSQL

## 1. 目标与结论

项目已经有较完整的前端本地处理基础：Excalidraw 白板、PDF.js/pdf-lib 文档处理、SheetJS/PapaParse 表格转换、CodeMirror 文档编辑、CropperJS 图片处理。没有必要为了“使用成熟组件”而全量重写。

本报告建议优先补充以下能力：

1. 用 **TanStack Query** 替代重复的手写请求缓存、加载状态与失效处理。
2. 用 **Dexie** 统一版本化的 IndexedDB 本地草稿与同步状态。
3. 以 **Web Worker + Comlink** 承载高 CPU 计算，避免阻塞 UI 主线程。
4. 用 **Univer** 补齐独立工作簿、公式与表格编辑，而不是继续扩展自写公式引擎。
5. 用 **Arquero / Perspective** 补齐客户端汇总与透视，保留 MUI X Charts 作为常规图表实现。

**架构不应变成“后端只透传任意数据库操作”。** 推荐的边界是：前端负责计算与交互；后端负责持久化、鉴权、事务、版本控制和可信的外部访问。

## 2. 当前盘点

依据 `web-react/package.json`、`server/requirements.txt` 与当前模块结构：

- **前端 UI：** MUI、MUI X Data Grid / Charts、dnd-kit、CodeMirror。
- **浏览器内文件处理：** PDF.js、pdf-lib、SheetJS CE、PapaParse、Mammoth、docx、Turndown、DOMPurify、CropperJS、heic2any、fflate。
- **白板：** Excalidraw，已有 IndexedDB 草稿封装和自动保存。
- **值得前置的后端性能操作：**
  - `server/app/services/table_expressions.py`：公式、关联查找和汇总。
  - `server/app/services/dashboard*.py`、`virtual_tables.py`：数据和图表聚合。
  - `server/app/routers/transfers.py`、`workbook_files.py`：Excel 解析与导出。
- **应保留后端的高可靠职责：** 登录与权限、版本冲突、事务、文件归属、Agent 暂存审批、备份与恢复。

## 3. 推荐优先引入的组件

| 组件 | 开源许可 | 在本项目中的用途 | 优先级与注意事项 |
| --- | --- | --- | --- |
| **TanStack Query** | MIT | 请求缓存、失效、错误与加载状态、mutation 后同步 | **P0**。先替换一个页面，不要求全仓同时迁移。它是服务端状态管理，不替代本地编辑状态。 |
| **Dexie** | Apache-2.0 | 对 IndexedDB 的事务、版本化 schema、草稿和同步元数据 | **P0**。统一现有文档与白板草稿入口；不等于持久化保证，仍需处理配额与备份。 |
| **Comlink + Web Worker** | Apache-2.0 | 小型、异步的 Worker 接口；承载公式、聚合、转换 | **P0**。提供取消、超时、序列号隔离和传输分片；不要把全量数据反复复制到多个 Worker。 |

参考：[TanStack Query](https://tanstack.com/query/latest/docs/framework/react/overview)、[Dexie](https://dexie.org/docs/Tutorial/React)、[Comlink](https://github.com/GoogleChromeLabs/comlink)。

## 4. 业务组件选型

| 功能 | 推荐选择 | 替代/保留意见 |
| --- | --- | --- |
| **独立工作簿与公式** | **Univer**（Apache-2.0），优先独立路由 PoC | 可补齐公式、编辑和工作簿渲染；应验证包体积、内部数据转换、XLSX 往返和中文体验。[项目](https://github.com/dream-num/univer) |
| **只求替换公式引擎** | HyperFormula 可做技术备选 | 开源分支为 **GPLv3 / 商业双许可**，不是 MIT；许可证与项目预期相容才采用。[许可证](https://raw.githubusercontent.com/handsontable/hyperformula/master/LICENSE.txt) |
| **其他旧表格库** | **不采用 Luckysheet** | 上游已停止维护并建议迁移到 Univer。[仓库说明](https://github.com/dream-num/Luckysheet) |
| **主业务数据表 UI** | 保留 **MUI X Data Grid** | 当前分页、筛选和编辑都能复用。MUI 官方 Pivoting 属 **Premium**，不能假定社区版免费提供。[官方说明](https://mui.com/x/react-data-grid/pivoting/) |
| **客户端聚合** | **Arquero**（BSD-3-Clause）起步 | 适合在已取得的数组数据上转换/聚合；不是持久数据库。[项目](https://github.com/uwdata/arquero) |
| **复杂汇总/透视交互** | **Perspective**（Apache-2.0）评估 PoC | 浏览器 WebAssembly 引擎、数据网格、透视与图表，适合作为完整分析模块，而非再叠一个图表插件。[项目](https://perspective-dev.github.io/) |
| **图表** | 默认保留 MUI X Charts，复杂时再选 ECharts（Apache-2.0） | ECharts 提供大数据增量渲染/流加载，但迁移会有样式、导出与联动成本。[官网](https://echarts.apache.org/) |
| **XLSX / CSV / 文档互转** | 保留 SheetJS CE + PapaParse；ExcelJS（MIT）按需选型 | ExcelJS 更适合样式丰富的 XLSX 操作，但官方明确浏览器包不包含流式读写器，不能拿 Node 能力规划前端大文件方案。[ExcelJS](https://github.com/exceljs/exceljs) |
| **PDF 与图片** | 保留 PDF.js、pdf-lib、CropperJS 和当前模块 | 浏览器本地处理已符合目标；没有必要为“成熟组件”换库。 |
| **白板** | 保留 Excalidraw，增强草稿持久化与并发控制 | 优先考虑 Dexie 封装草稿与同步元数据，避免引入第二套画布。 |
| **笔记 / 文档编辑** | 保留 CodeMirror + Mammoth + docx + Turndown | 若明确需要所见即所得，再选 TipTap 核心（MIT）；需注意其 DOCX 转换商业功能不是所有核心编辑器能力的一部分。[TipTap](https://tiptap.dev/) |

## 5. 审慎使用的可选方向

| 组件 | 适用情形 | 暂不默认采用的原因 |
| --- | --- | --- |
| **DuckDB-Wasm** | 用户需要在浏览器内进行灵活 SQL/OLAP，且愿意维护 WASM 与 Worker 部署 | 当前表格范围有限，先用 Arquero/Perspective 可以得到较小变更；真实导入/内存/构建开销需先验证。[文档](https://duckdb.org/docs/clients/wasm/overview) |
| **PGlite** | 明确转向 local-first、离线优先与客户端同步的产品 | 会增加数据同步、冲突、迁移和离线一致性设计；不适合作为通用性能补丁。[项目](https://github.com/electric-sql/pglite) |
| **RxDB / Dexie Cloud 等完整同步产品** | 要求多端实时同步与离线写入 | 当前项目是单用户后台数据库持久化，先不要把同步基础设施当作新需求引入。 |

## 6. 推荐计算边界

### 6.1 前端负责

- **查看/编辑运算：** 表格查看、选中、排序、已加载范围内的计算。
- **公式与聚合：** 工作簿公式、计算列、关联查找、汇总与透视、看板图表结果。
- **文件操作：** 浏览器内的 PDF、图片、文档转换及 Excel 导入导出。
- **草稿与本地任务：** 文档、白板、分析快照、Worker 取消状态和增量处理进度。

主要原则：CPU 重计算进入 Worker，主线程只做 UI 协调和结果展示；大数据使用分片、取消和背压，避免“移到了前端却一次性把全库载入内存”。

### 6.2 后端必须保留

- 登录、Cookie/CSRF、Token 范围与资源所有权校验。
- 权威版本、事务、幂等、级联删除/恢复、Agent 审批、操作审计。
- 对正式记录的校验与基线更新；不能把浏览器计算结果无条件当成可信正式数据。
- **第三方 AI / 翻译代理：** 密钥永远只在服务端解密与使用；浏览器负责整理输入/输出及可公开的分析，不暴露第三方凭据。
- **RSS / 书签网页元信息抓取：** 浏览器直连会遭遇 CORS 和来源直接暴露问题；是否改为用户客户端网络抓取需另行做隐私与网络安全设计，不能直接删除现有服务端防护。
- **完整备份/恢复/清理：** 浏览器不拥有全量数据库和全部运行上下文。这些任务应在服务端或独立运维任务系统执行，不能因 API 计算前移而自行丢弃。
- 截止、逾期等业务时间规则仍以服务端时间及约定时区为准。

## 7. 数据与接口设计约束

1. **明确数据权威：** 服务器保存正式记录和版本；前端本地保存“可恢复的工作副本”，不通过浏览器声明覆盖正式状态。
2. **分析快照：** 若看板使用整表计算，明确 `schema_version`、数据版本、加载时间、行数和完整性；发生更新时让用户刷新或失效重算，避免在旧快照上混入新数据。
3. **大表分层：** 当前页的即时编辑沿用分页接口；只有用户选择的前端分析任务才下载需要的数据。大表必须有分片、上限和取消机制。
4. **Agent 与浏览器一致：** 代理写入继续按既有暂存校验流程。不能让前置公式绕过校验或跳过版本检查。
5. **深模块设计：** 给 Worker、草稿和文件转换提供小且稳定的接口，把库版本、序列化和重试细节藏在实现内部，而不是让每个页面直接了解多个库细节。
6. **离线限制：** Dexie/IndexedDB 是本地可恢复能力，不承诺跨设备或清理浏览器数据后仍能找回。正式备份仍由服务端提供。

## 8. 落地顺序与验收

### 第一阶段：请求、草稿与 Worker 基础设施

- 选一个高刷新页面接入 TanStack Query，保留既有 Axios 客户端、CSRF、401 处理。
- 用 Dexie 试迁一个文档草稿；验证配额、写入失败、账号隔离和版本迁移。
- 让一个读聚合功能进入 Worker；支持取消、超时和过期响应隔离。
- **验收：** 常规流程功能不退化，弱网/刷新/重试/文件配额异常可见；长计算期间按钮与滚动不阻塞。

### 第二阶段：独立工作簿 Univer PoC

- 先放在独立路由，保持原工作簿可回滚。
- 明确本地模型 ↔ 服务端保存快照的数据转换。
- **验收：** 常用函数、跨表引用、公式错误、Excel 导入导出、中文、撤销重做、保存冲突和移动设备。
- 测首屏传输、初始化、公式重算耗时和内存；不默认它一定比现有实现更快。

### 第三阶段：只读聚合与分析

- 优先迁移看板/透视读操作，不改正式记录的权威接口。
- 试点 Arquero 处理有限数据集；若复杂透视交互明显增加自写成本，再评估 Perspective。
- **验收：** 新旧实现结果一致，数值精度/空值/日期/关联与失效快照明确，测试覆盖 1 千、1 万行及上限场景。

### 第四阶段：Excel 与计算列迁移

- 逐类迁公式、关联、汇总、导出；保留旧 API 供 Agent 和过渡客户端使用，直到版本化弃用。
- 检查大文件浏览器内存、ZIP 展开上限、安全清洗和公式等非标准事实的展示方式。
- **验收：** 整批原子性、校验错误行、用户取消、失败重试与刷新恢复都要保留；校验通过后仍由后端事务提交正式变更。

## 9. 不推荐的做法

- 为了前置计算，把整库一次性拉到浏览器跑所有列表和查询。
- 把 AI/翻译密钥交给前端，或让浏览器无条件抓取任意 URL。
- 将完整备份、恢复、清理、Agent 审批与正式版本控制也移到客户端。
- 同时引入 Univer、Perspective、DuckDB-Wasm、PGlite，导致多份引擎/状态与巨大传输包。
- 以开源库“有功能列表”代替 PoC；不检验其许可证、浏览器运行方式、大小和实际保存兼容性。

## 10. 调研边界

本文依据项目代码和候选库官方资料进行选型分析。没有安装依赖或跑生产 PoC；各候选库的许可证、浏览器部署模式及导出/迁移保真度，仍需要在实际引入版本时复核。

### 11.2 验证

- `npm run typecheck` 通过。
- `npm run build` 通过，152 个资源，16.7 MB → 4.9 MB Brotli；构建产物包含独立 Worker chunk。
- Playwright 本地开发模式：
  - 热榜缓存页面可渲染，切走再回来后不再出现首屏加载块。
  - 文档草稿写入 IndexedDB（`schemaVersion=1`、`userId` 正确），刷新后可恢复；丢弃后记录删除。
  - 旧 `localStorage` 草稿可迁移，迁移后旧键被移除。
  - 汇总校验分组计数、切换合计和交叉透视均正常，浏览器实际启动 `analysis/worker.ts`。
  - 全流程无 `pageerror`。
