# 弹窗布局约定

项目的 Element Plus 弹窗、抽屉和确认框统一使用 `web/src/styles/overlays.css`。普通弹窗按内容决定高度，最大 800px，且始终受当前动态视口与安全边距限制。标题、关闭按钮和底部操作区不参与正文滚动；长表单、历史正文等在 body 内滚动，页签导航保持可见。抽屉同样保持标题和底部操作区可见，窄屏宽度不超过视口。

图表配置使用 Element Plus Tabs，分成“数据与图表”“显示与筛选”“数据预览”；点击预览自动进入预览页签，切换页签保留配置。帮助示例默认折叠。翻译详情在原文、译文间切换，避免两个长文本滚动框再叠加外层滚动。便利贴全文和笔记历史直接使用统一正文滚动。

新弹窗继续使用标准 `el-dialog` 和 footer 插槽即可。不要给整个弹窗设置业务内容的固定高度，不要把保存按钮放在长表单最末尾，不要另加一层整页纵向滚动。数据表格、PDF、AI 双栏等确有独立浏览区域时，可保留其内部滚动。真正的全屏模式仍占满视口。

浏览器回归：先在 web 目录运行 `npm run build`，再从项目根目录运行 `server/.venv/bin/python e2e/run-modal-layout.py`。测试启动独立 SQLite 服务，生成长表单与长文本数据，验证笔记本、手机、矮屏的边界、固定操作区、页签切换，以及嵌套字段和记录保存。测试不会连接本地工作台数据库，结果截图位于忽略目录 `.run`。
