# 虚拟表与数据可视化

入口：表格列表或侧边栏“表格”下的“新建虚拟表”。虚拟表与原始表一同列出，并带有“虚拟表”标记。

## 创建和使用

1. 输入名称，选择 2–8 张原始表。
2. 选择组合方式，检查匹配键、输出字段及类型。
3. 按需添加结果计算列、筛选和排序，点击“预览结果”。预览显示前 100 行及完整结果行数。
4. 保存后得到只读虚拟表；可搜索、排序、导出 CSV、查看每行的来源。
5. 点击“用于数据可视化”，选择已有看板或新建看板，然后配置图表。图表来源列表也可以直接选择带“虚拟表”后缀的表。

保存的是组合规则，不是数据副本。修改原表后，虚拟表下次读取或刷新重新计算；已有图表刷新时读取当前结果，看板保留原来的每 60 秒刷新机制。多张图表可以复用同一张虚拟表，同一看板请求中同来源只计算一次。

## 三种组合方式

| 方式 | 规则 | 适用的数据结构 |
| --- | --- | --- |
| 上下追加 | 按输出列映射把来源记录逐行追加，不自动去重；未映射的来源列补空值 | 多张同类明细表 |
| 按字段关联 | 按 1–3 个共同键精确匹配，然后并列输出字段；支持左关联、内关联、全关联 | 主表及其补充信息 |
| 汇总后对齐 | 各来源先按共同键分组，分别求和、平均、最小、最大或计数，再对齐各组指标 | 来源粒度不同，需先统一口径 |

左关联以来源列表的首张表为主表；选择顺序决定来源顺序。数字键按数值比较，日期按 ISO 日期比较，单选按选项名称比较，文本区分大小写，不自动去除空格。任何一个匹配键为空，该记录不会与其他来源的空键配对；汇总对齐中的空键记录也单独保留。

关联模式默认拒绝其他来源中的重复键，避免意外重复累计。确实需要一对多或多对多配对时，显式勾选允许重复匹配，结果会继续显示警告。该选项不会解除行数限制。若只是希望比较各来源指标，优先用“汇总后对齐”。没有匹配来源的数据保留空值，公式中可用 `COALESCE({指标},0)` 明确补零。

## 计算、追踪与编辑

- 数字使用 Decimal 计算并以字符串返回，避免 `0.1 + 0.2` 的浮点误差。公式沿用原表受限表达式引擎，支持字段引用、四则运算、IF、COALESCE、ROUND 等；不执行 Python 或 SQL。
- 计算列逐单元格展示错误。图表统计涉及错误字段时显示错误，CSV/Excel 导出保留 `#ERROR`，不会用空值掩盖。
- 单选、多选、关联及附件字段可转换为文本输出；关联输出的是显示名称，不是可编辑的关联关系。数字、日期、勾选输出转换失败时明确报错。
- 点击“数据来源”可跳到原表记录详情；每行保留最多前 100 条来源及完整来源条数。虚拟记录使用独立的负数 ID，不是原始记录的写入入口。
- 编辑规则需重新预览后保存。规则使用版本检查；冲突时保留草稿，支持导出 JSON 规则备份。离开未保存的编辑页需要确认。备份当前用于保存配置，不提供自动导入或跨环境 ID 重映射。
- 原表/字段改名依赖稳定 ID/字段 key；删除来源后结果明确报错，不展示过期数据。修复入口仍可打开。重建输出字段可能影响已有图表，需要重新配置引用的字段。

## 当前边界

这是现有 FastAPI 查询层上的受限实时计算模块，图表继续使用现有编辑器；本次没有嵌入 Metabase、DataEase、Superset 或 Graphic Walker，也没有搭建独立 BI 服务。

每张来源最多 10,000 行，来源合计最多 20,000 行；涉及关联计算的全部加载最多 40,000 行。输出字段（含匹配键）最多 50 个，筛选最多 10 条，排序最多 3 条。中间关联结果、汇总组和最终组合结果最多 10,000 行；**结果筛选之前即检查规模**，不能用最后的筛选绕过限制。超过上限会报错，不静默截断。单元格文本最多 20,000 字符。

来源目前只支持原始表，不支持嵌套虚拟表、自关联、任意 SQL、跨数据库查询、物化缓存或写回合并结果。多来源读取不承诺跨表的同一时点快照。虚拟表不能导入记录、编辑单元格或创建独立工作簿；修改应在原表或组合规则进行。现有账号与 Agent 权限继续生效，不新增公开访问入口；Agent 的表格读取接口能读取虚拟结果，写入会拒绝。

部署前执行数据库迁移 `alembic upgrade head`，新版本为 `f36a84c705d9`，为 `data_tables` 增加 `kind` 和 `virtual_config`。已有表默认是原始表；迁移不重建父表。SQLite 和 PostgreSQL 的升级、降级、再升级已在隔离环境演练。
