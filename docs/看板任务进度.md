# 看板任务进度

入口：数据可视化 → 进入看板 → 添加图表 → 任务进度。无需更改原表字段或数据库结构，配置与已有图表一起保存，可编辑、移动、删除、独占一行。

## 两种计算方式

- 按任务数量：一条记录代表一项任务，设置完成条件（例如状态等于已完成、已核对等于是），目标可选择范围内任务总数或固定整数。
- 按数值累计：选择完成量列，目标选择另一数字列的合计或固定正数；使用 Decimal 汇总，避免浮点累积误差。按行同时检查完成量和目标量；任意一侧为空、无效或负数时整行不参与计算，并提示忽略行数。

支持进度条／圆环，使用 Element Plus Progress 组件。可选文本、单选、勾选、日期分组；分组展示独立进度条。总进度按实际量合计 / 目标量合计计算，不平均分组百分比。

固定目标与分组一起使用时，目标表示「每组目标」，总目标 = 固定目标 × 全部分组数；分组展示数量限制只影响显示，不影响总量。超过目标时保留真实百分比，图形填充最多 100%，剩余量不小于零。目标为零显示暂无有效目标，空表显示暂无任务。固定目标范围 0.000001–10¹⁸，任务数量目标必须是整数。

## 统计范围与时间

最多 7 个条件，全部同时满足；支持字段类型对应的等于、不等于、包含、为空、数值或日期范围比较。可与看板顶部时间范围叠加，起止日期均包含在内。没有配置日期列时明确提示不参与时间筛选。

按任务数量时可选择截止日期列：日期早于北京时间当天且未完成的记录计入「逾期未完成」，当天到期不算逾期。

点击「查看来源记录」或分组名称进入原始表，并带入范围、时间和分组条件。即使用户上次打开的是自由工作簿，也会进入带筛选的原始表。此功能不会修改原表。

## 性能和边界

按来源表共享进度卡数据扫描，每批 1000 行；普通表最多 100000 行，含相关计算列最多 10000 行，最多 2000 分组。超限或参与统计的计算列报错时显示错误，不返回部分进度。复用来源版本缓存，原表记录或结构更新后缓存失效；看板每 60 秒刷新，可手动刷新。

已有指标卡、柱状图、折线图、饼图沿用原有计算路径。旧看板无需迁移，进度配置为可选字段。

## 验证

- 35 项任务进度与已有看板回归：任务／勾选完成条件、分组、日期、范围筛选、来源记录匹配、数值精度与加权、固定目标、零目标、空表、逾期、字段和选项失效、缓存刷新、1 万条记录及超限保护。
- 全套后端测试通过；另在独立 PostgreSQL 数据库执行同一组看板回归。
- `npm run build`：类型检查、生产构建。
- `e2e/dashboard-progress.mjs`：独立测试服务 `127.0.0.1:18186`，验证真实界面的任务／数值配置、预览保存、分组跳转、重开持久化、移动端与深色主题。测试脚本创建测试表与看板，仅用于隔离数据库。
